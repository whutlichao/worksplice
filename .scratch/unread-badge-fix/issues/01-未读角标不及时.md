# 01: 未读角标更新不及时（打开频道期间游标未推进）

**What to build:** 打开的 channel/DM 在查看期间收到新消息（agent 回复）时，持续推进已读游标（POST /api/channels/<id>/read），使切走后不再出现残留未读角标；未打开频道的未读语义与自己的消息不算未读保持不变。

**Blocked by:** 无。

**Status:** resolved

## 症状

1. 打开频道 A → `handleSelectChannel` 推进 `read_seq`，角标清零。
2. 停留 A，agent 回复（seq > read_seq、作者非 Owner）→ 服务端未读数增长。
3. 侧栏 15s 轮询把 `A.unread > 0` 写回 state（选中行不渲染角标，视觉不可见）。
4. 切到 B → A 不再 `isSelected`，残留角标出现（陈旧）。
5. 切回 A → 再次 `/read` 清零。

## 根因（已验证，非定论照单收）

- 服务层 `lib/domain/raft/reads.ts` + `markChannelRead` 语义正确（`reads.test.mjs` 全绿）。
- 缺陷在客户端：已读游标只在 `AppShell.handleSelectChannel`（选中时刻）推进一次；`useChannelData` 的 3s 轮询 effect（`applyPollPage` 合并出新消息、`next !== base` 时）没有任何代码再次推进游标。
- Tight 回路 `red-check.tmp.mjs`（已删）必红确认：`useChannelData` 无 `markChannelRead` 导出，轮询无法推进游标。

## 修复

- `hooks/useChannelData.ts` 新增纯函数 `markChannelRead(channelId, fetchFn)`（fetch 可注入，POST `/api/channels/<cid>/read`，fire-and-forget 语义由调用方持有）。
- 同文件 3s 轮询 effect 内：`applyPollPage` 返回新引用（即合并出新消息）时，对当前查看的 `cid` 追加 `void markChannelRead(cid).catch(...)`。`useChannelData` 只为当前选中频道挂载，天然满足「打开中」语义；`channelId` 为空时 effect 早返。
- DM 同 channel（`type='dm'` 的普通 channel 行，同 hook 路径），同理覆盖。
- `AppShell.handleSelectChannel` 的选中时 `/read` 保留（首屏语义）；服务层/路由不改语义。

## 验收

- [ ] 打开频道 A，agent 在 A 回复新消息，切到 B 后 A 无残留未读角标
- [ ] DM 同理：打开某 DM，agent 回复，切走后再看该 DM 无残留角标
- [ ] 未打开的其他频道有新消息时仍正常显示未读角标（回归不破坏）
- [ ] 自己的消息不产生未读（既有语义保持，回归锁定）
- [ ] tight 回路先红后绿 + `npm test` 全绿 + 无 `[DEBUG-]` 残留

## Answer

### 实现决策

- 新增 `hooks/useChannelData.ts` 纯函数 `markChannelRead(channelId, fetchFn)`（fetch 可注入，POST `/api/channels/<cid>/read`，返回 `readSeq`，缺字段兜底 0，HTTP 错误映射为 `Error`）。
- 3s 轮询 effect 内 `applyPollPage` 返回新引用（合并出新消息）时，对当前 `cid` 追加 `void markChannelRead(cid).catch(() => undefined)`（fire-and-forget，失败不干扰消息合并）。
- `useChannelData` 只为当前选中频道挂载，天然满足「打开中」语义；`channelId` 为空 effect 早返；DM 与 channel 同 hook 路径，同理覆盖。`AppShell.handleSelectChannel` 的选中时 `/read` 保留；服务层/路由零改动。

### 验证命令结果

- tight 回路（先红后绿）：修复前 `red-check.tmp.mjs` 断言 `markChannelRead` 为 function → 红（`'undefined' == 'function'`）；修复后 `green-check.tmp.mjs` → 绿（`/api/channels/c1/read` + POST + readSeq=2，`applyPollPage` 同一引用语义不变）。两脚本均为临时文件，已删除。
- 行为级验证 `e2e-check.tmp.mjs`（服务层语义镜像）：打开→已读→agent 回复→`unreadCount=1`（旧残留）→模拟轮询 `/read`→`unreadCount=0`；自己的消息不算未读 → 绿。已删除。
- `node --test hooks/useChannelData.test.mjs`：30/30 通过（含新增 3 个 `markChannelRead` 用例：正常/404 映射/缺字段兜底）。
- `npm test`：432/432 全绿。`tsc --noEmit` 干净。`npm run lint` 与改前基线一致（10 problems，均为既有，无新增）。
- `grep DEBUG-`：`hooks/useChannelData.ts`、`components/AppShell.tsx` 零残留（本次未使用 debug 日志）。
