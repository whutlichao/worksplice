# 01: 轮次记录（round_logs）的失败可读性

**What to fix:** 可观测面板要能回答「agent 为什么失败」，且面板每一格的字段都得是真的。三个缺陷：D1 失败原因被吞（round_logs.reason 恒为通用文案 "model returned no text (request failed?)"）、D2 轮次出线形状是 snake_case 而面板读 camelCase（空白 target / 光秃秃 `#` / "Invalid Date"）、D3 `get_state` 的 model 形状 `{id, provider}` 被误当 `{provider, modelId}`（面板显示 "new-api/—"）。

**Blocked by:** 无。

**Status:** resolved

## 症状

- **D1**：模型/API 报错（实测 new-api 429 `FreeUsageLimitError`）后，面板轮次行只显示「model returned no text (request failed?)」，看不到 429 正文；真实原因只在 session jsonl 的末条 assistant message（`stopReason:"error"` + `errorMessage`）里。
- **D2**：轮次行的 target 渲染为空、`#` 后无数字、时间渲染成 `Invalid Date`（`formatTime` 的 try/catch 拦不住——`new Date(undefined).toLocaleString()` 不抛错，直接返回字符串 "Invalid Date"）。
- **D3**：runtime 区「当前运行」显示 `new-api/—`。

## 根因（tight 回路证实）

- **D1**：`lib/agent-loop/loop.ts` 的 `promptSession` 在 `get_last_assistant_text` 为空时硬编码通用文案；而 pi SDK 对模型/API 报错**不 reject** `prompt()`（事件流照发 `prompt_done`、`getLastAssistantText()` 返回 undefined）。真实原因只落在 `AgentSession.messages` 末条 assistant 的 `stopReason`/`errorMessage` 上——没有任何只读命令能把它取出来。
- **D2**：`lib/domain/collab/rounds.ts` 的 `listRoundLogs` 返回数据层原始行 `RoundLogRow`（`target_id`/`base_seq`/`created_at`），`app/api/members/[id]/observability/route.ts` 直接透传；面板读 `round.targetId`/`baseSeq`/`createdAt` → 三字段全 `undefined`（同一载荷里的 timeline 是 camelCase，两条出线形状不一致）。
- **D3**：两个路由把 `get_state` 的 model 断言成 `{provider, modelId}`，而 `lib/rpc/session.ts` 的 `get_state` 实际返回 `{id, provider}`（`app/api/agent/new/route.ts:57-64` 是正确的 `state.model.id` 写法）。

## 修复

- **D1**：`lib/rpc/session.ts` 新增只读命令 `get_last_assistant_error`（从 `this.inner.messages` 末条 assistant 取 `stopReason`/`errorMessage`，选取口径与 `getLastAssistantText()` 对齐——跳过 aborted 且无内容项；**不改** `getLastAssistantText()` 语义，既有消费方零影响）。`lib/agent-loop/loop.ts` 的 `promptSession` 空文本分支改走新增的 `emptyTextFailureReason(session)`：拿到 `errorMessage` 即 `model error: <原文>`，拿不到（fake 会话返回 null，或抛 `Unsupported command`）回落原文案。**不改** ack/重试/游标语义：仍 `status=error`、不 ack、下次 wake 重试。
- **D2**：`rounds.ts` 新增出线类型 `RoundLogView`（camelCase，`createdAt` 为写侧 `insertRoundLog` 的 `new Date().toISOString()`）并让 `listRoundLogs` 翻译出线；`components/AgentDetailPanel.tsx` 的 `formatTime` 改为先验 `getTime()`，非法日期回落 `—`（与面板其它缺值一致），不再输出 "Invalid Date"；轮次列表照 `TaskHistoryList` 先例抽成可独立渲染的 `RoundLogsList({ rounds, t })`，使渲染级断言落在真实 markup 上。
- **D3**：两个路由按 `app/api/agent/new/route.ts` 的写法映射 `{ provider: state.model.provider, modelId: state.model.id }`。
- **顺手（工具门禁驱动的等价重构，见 Review 处置）**：`lib/rpc/session.ts` 里 9 处 `{...} as ExtensionUiRequest as AgentEvent` 收敛为一个带 SAFETY 注释的 `asAgentEvent()` 宽化函数（运行时等价）；`send` 命令分支计数注释 27 → 26。

## Answer

### 实现决策

1. **D1 的机制选只读命令而非直接读 jsonl**：loop 侧只依赖结构接口 `LoopSession`（fake 可注入），加一条命令 = 在 `lib/rpc/session.ts` 的唯一 dispatcher 里取 `this.inner.messages`；loop 不需要知道会话文件在哪。回落是三重的：命令返回 `errorMessage: null`、命令不存在（fake 返回 null）、命令抛错（真 SDK 的 default 分支抛 `Unsupported command`）——`await ... .catch(() => null)` 全兜住，既有 fake 一个没挂（`npm test` 全量 1089 绿为证）。
2. **不改 `getLastAssistantText()`**：新命令独立选取，口径照抄它的 aborted-空内容跳过规则；`hooks/useAgentSession.ts` 等既有消费方零改动。
3. **D2 在服务层翻译而不是在路由/面板打补丁**：`Store` 契约的 snake_case 行不出数据层，出线统一 camelCase——与同载荷 timeline 的形状一致，路由保持薄封装（`rounds: listRoundLogs(agent.id)` 一行不动）。面板侧 `formatTime` 的回落选 `—` 而非原样回显非法字符串：与面板其它缺值占位一致（`round.reason || "—"`、`modelId ?? "—"`）。
4. **D3 以 `app/api/agent/new/route.ts` 为准**（spec 指定）：断言形状改成 `{id, provider}`，映射发生在路由边界；`Object.keys(live.model)` 逐字断言 `['modelId','provider']`，防止将来又退化成透传。
5. **轮次列表抽 `RoundLogsList`**：spec 明确要求「照既有 TaskHistoryList 先例」，且 SSR 丢弃 key、仓库无 jsdom ⇒ 渲染级证据只能落在 RSC 的 `renderToStaticMarkup` 输出上。抽取后面板本体改为一行 `<RoundLogsList rounds={obs.rounds} t={t} />`，可见文案/样式逐字未动。
