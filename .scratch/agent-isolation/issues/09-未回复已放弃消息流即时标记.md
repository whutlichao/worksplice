## Question

07 Q3 选项 b（当时暂缓，fog 毕业）：频道消息流内给触发消息一个「未回复（已放弃）」badge——不打开详情页就能看出「别等了」。round_logs 已落地（schema v9，driver 唯一收口点，`lib/raft/rounds.ts`），数据可查；本 ticket 收敛标记形态并实现落地。

**待收敛的小决策（实现时一并定）：**

- **什么状态算「已放弃」**：`silent`（cap-ack / 重试耗尽）确定算；`error`（会话失败，下次 wake 重试）与 `busy-cwd`（02 后 driver 会等占用会话 settle 后重试）严格说不是「已放弃」；`yielded`（任务让路）更不是——badge 语义 = 「这轮到此为止，别再等」，别把会重试的轮标成放弃
- **锚定哪条消息**：round_logs 的 `(target_id, base_seq)` 记录的是 agent 读到/被告知的房间版本——触发消息 = 该 target 内 `seq == base_seq` 的消息？还是该轮 wake 实际由哪条消息引起？前者确定性强（base_seq 是持久化事实），后者需回推唤醒链路（wake hint 不落库）
- **标记生命周期**：同一 agent 对该 target 后续轮次 `replied` 后标记是否消失？round_logs ring cap 200 删除旧行后标记自然消失是否可接受（还是落一张「放弃标记」表）
- **UI 形态**：消息行内小字 badge（lucide 图标 + 文案），hover 可看详情（跳详情页轮次记录）

## Answer

### 决策（实现时收敛，全部按推荐落地）

1. **已放弃判定 = `isAbandonedRound(status, reason)`**（rounds.ts 单一事实来源，导出可测）：`silent` 算；`error` 且 reason 匹配 `capped at \d+` 算（cap-ack 逃逸口，游标已推进、不会再来自动重试——07 语义里 cap-ack 就是「已放弃」）；普通 `error`（下次 wake 重试）、`busy-cwd`（driver 等 settle 后重试）、`yielded`（任务让路）、`ignored`（05 正常协议选择，07 决策 4 规定仅可观测页可见）**不算**。
2. **锚定 = base_seq 持久化事实**：标记锚在该 target 内 `seq == base_seq` 的消息（cap-ack 与 silent 的 baseSeq 均为 agent 读到/被告知的房间版本；wake 链路不落库，回推不可行且不确定）。无对应 seq 的消息不显示。
3. **生命周期 = 派生自 round_logs，不落专门表**：每 (agent, target) 只看**最新一轮**——最新轮是已放弃才标，之后任何轮（replied/ignored/error/…）自动清除标记（「等待已解除」）；ring cap 200 裁掉旧行 = 标记自然消失，可接受（只影响「已放弃后该 agent 又跑了 200+ 轮」的边缘，此时对话早已翻篇）。查询 = 新 db 方法 `listRoundLogsByTarget`（rowid 倒序）+ 服务层按 agent 取最新。
4. **UI = MessageRow 头部小字 badge**：lucide `CircleSlash` + 文案「未回复」；多 agent 放弃同一条消息时聚合为「{count} 人未回复」；title tooltip 列出 `agent：reason` 明细；点击打开该 agent 右栏详情面板（轮次记录在可观测页）。线程消息经同一 `listMessages` 通道自动带出标记（线程轮次按线程自己的 seq 空间锚定）。
