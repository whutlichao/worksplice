# 07-状态点回应可观测性

Type: grilling
Status: resolved（2026-08-12）
Blocked by: （无）

## Question

05 落地「全量唤醒 + 自判回应」后，状态点对「已回复 / 自判 ignore / 失败」无可分辨——UI 上 agent 不回复时，用户无法区分「它看了消息决定不理（正常协议选择，ignore）」与「它没处理（失败：空文本 / reply 无 content / 确定信号下 ignore 等）」。「该回不回」的感知相同，但性质不同：前者是 agent 的自主判断，后者是需要排查的故障。

**决策：可观测性的形态与粒度。**
- 状态点是否扩展（如 error 细分 reason / 新增「ignored」态），还是保持四态 + 在 agent 详情面板（可观测性页）提供轮次结果明细（每轮：status / reason / baseSeq / target / 时间，来源 = RoundOutcome 落盘或日志）
- 兜底 cap-ack（连续 2 次确定信号下 ignore 后游标推进）在 UI 上的呈现：现在只有 error 状态点，用户看不到「已放弃」——是否需要专门标记
- 「ignore（正常）」是否需要在任何 UI 上可见——还是仅日志/详情页，状态点保持安静（避免把正常协议选择当噪声刷屏）

## Answer

### 决策（两轮 grilling，全部按推荐收敛）

1. **载体 = 落盘 round_logs 表**（schema v9，仿 reminder_logs v4 先例）：可观测页展示全量历史、重启不丢、可事后翻旧账（「状态回 online 才发现没回复」本质是事后排查）。只记**有结论的轮次**（replied/ignored/silent/anyway/yielded/error/busy-cwd），noop/skipped/busy 瞬态不记。
2. **状态点保持四态不动**：粗粒度在场信号，失败已由 error 覆盖；「自判 ignore」上状态点 = 把 05 的正常协议选择当异常刷屏，与 05 语义相悖。
3. **cap-ack「已放弃」= 可观测页轮次明细可见**：reason 自带 `(capped at 2)` 标记（loop.ts 原 reason 文案），error 红点维持被动可见性；不做消息流内 badge（Q3 选项 b 暂缓，见 map Not yet specified）。
4. **正常 ignore 仅可观测页轮次明细可见**（status=ignored 一行，标注为正常选择）——这是「该回不回」两种性质（自判 vs 失败）唯一的非刷屏区分手段。
5. **术语**：CONTEXT.md 补「轮次 (Round)」「轮次结果 (Round Outcome)」（回应判断的执行载体与产物）。
