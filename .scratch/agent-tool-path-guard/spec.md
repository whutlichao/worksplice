# spec: agent 文件工具的路径边界

Type: spec
Status: ready-for-agent
Design: `docs/agent-file-tool-path-guard.md`
ADR: `docs/adr/0011-agent-file-tool-path-guard.md`（决策一至五）
Grilling 票: `.scratch/agent-tool-path-guard/issues/01-agent-file-tool-path-guard.md`（resolved）

## Problem Statement

worksplice 的每个成员（agent）就是一个 pi 会话，拿的是 pi 原生的文件工具。身份隔离只到消息与游标
这一层——频道、任务、唤醒、backfill 归属都有门禁，但成员调起文件工具时，落点是**本机文件系统上的
任意绝对路径**，与它属于哪个成员无关。

最坏后果是可预见的：`worksplice.db` 一可读，一次提示注入即可拖走全部私有频道正文、成员表
（含 provider / modelId / home_path）、任务表、reminder 表。数据库与被保护对象住在同一棵目录树下。

从人类 Owner 的视角：现在**无法回答「这个 agent 能看到什么」**这个问题，因此也无法在它越界时
察觉。owner 唯一能做的事是在 agent 的文字回复里事后发现它抱怨读不到文件，或者完全发现不了。

## Solution

给六个文件工具（`read` / `write` / `edit` / `grep` / `find` / `ls`）加一层**路径守卫**：
每个成员有一份**允许根**（自己的家目录 + 自己显式绑定的项目目录），落在根外的调用被拒绝，
且拒绝时错误文本列出该成员当前的允许根。

守卫落在 pi 六个工具各自的 `operations` 接缝上（这些工具在触碰实际 fs 之前已把参数解析成绝对路径），
由 worksplice 自己的 pi 扩展工厂经**既有**的 `extensionFactories` 接缝注册同名定义覆盖内置实现，
主流程零改动。

`worksplice` 的数据目录永远不是允许根——写成显式不变式，不是「恰好不在列表里」。

## User Stories

1. 作为人类 Owner，我想让每个成员只能读改自己家目录与绑定项目目录下的文件，这样一次提示注入无法拖走数据库。
2. 作为人类 Owner，我想 `worksplice.db` 永不可达，这样私有频道正文与成员表不会因注入泄露。
3. 作为人类 Owner，我想让附件目录不可枚举，这样我发在频道里的附件不会被批量翻走。
4. 作为人类 Owner，我想在越界发生时从 agent 的错误里直接看出它在试什么，这样我能事后判断是否被盯上了。
5. 作为人类 Owner，我想六个文件工具都受同一份约束，这样 agent 改用 `grep` 不会绕过 `read` 的守卫。
6. 作为人类 Owner，我想共享项目目录下的多个成员仍能互读互写，这样它们在同一个代码库分工不会互相踩踏。
7. 作为人类 Owner，我想明确知道本票拦住了什么、没拦住什么，这样我不会误以为隔离已经完成。
8. 作为成员，我想在自己的家目录内自由读写，这样我的记忆文件与草稿照常工作。
9. 作为成员，我想在显式绑定的项目目录里读写，这样我能完成落到我名下的代码任务。
10. 作为成员，我想越界错误明确说出「哪个绝对路径被拒」，这样我能自我纠正而不是换路径瞎试。
11. 作为成员，我想错误里附上我的允许根清单，这样我知道边界在哪，而不是反复撞墙烧轮次。
12. 作为成员，我想家目录里指向家目录外的符号链接被拒绝，这样符号链接不能当后门。
13. 作为开发者，我想允许根判定是一个零 SDK 依赖的纯函数，这样前缀陷阱、符号链接、不存在路径这些边界形态能被穷举测试。
14. 作为开发者，我想判定逻辑自身出错时一律拒绝，这样故障不会退化成放行。
15. 作为开发者，我想守卫在会话 reload 之后仍然生效，这样资源重载不会静默丢掉隔离。
16. 作为开发者，我想覆盖后的工具定义仍带 pi 原有的提示片段与编辑准则，这样模型不会因为接入守卫而失去精确编辑行为。
17. 作为开发者，我想守卫覆盖的工具集合从唯一事实来源派生，这样将来新增工具时不会漏掉约束。

## Implementation Decisions

完整论证见 ADR-0011，此处只列结论：

1. **允许根** = 一个具体的目录列表：成员自己的家目录 + 该成员显式绑定的项目目录（若有）。根的构成复用既有家目录派生规则（ADR-0001），不新造第二套目录解析。根在会话创建时算一次并随会话持有——换工作区本身就会销毁旧会话，不存在旧目录权限挂在活会话上的窗口。
2. **显式不变式**：永不纳入允许根的是 `~/.worksplice` 作为根本身、`worksplice.db`、`attachments/`、其他成员的家目录。逐条列明而非「默认不包含」。措辞上必须区分两件相反的事：排除的是「这个根本身可整棵可达」，不是「这个根下不许有任何路径」——成员自己的家目录恰在被排除的父目录下，作为更窄的单独条目显式开口。
3. **共享项目目录不是漏洞**：ADR-0001 明确允许多成员绑定同一项目目录，互读写是有意设计，本票不收这个口子。
4. **注入点**：pi 扩展工厂经既有接缝注册同名定义覆盖；主流程零改动。另两条路线被否决且各有具体理由——一条要退回更低层的会话组装（重做 ADR-0007 判给 pi 的地盘），一条拿不到绝对路径且看不见遍历途中的实际读取。
5. **覆盖定义必须由 pi 自己造**：同名覆盖是整条定义替换，手写会静默丢掉提示片段、编辑准则与 diff 渲染。
6. **越界处置**：报错，且错误文本列出该成员当前允许根。**不清静改写**（重定向会让模型以为自己读到了目标文件，比拒绝更坏）、**不静默截断**（同样让模型拿到「看起来能用」的错误内容）。
7. **路径判定三条硬要求**：realpath（取最深存在祖先 + basename 回退，因为 pi 的路径解析只归一化、不 realpath，根内符号链接指向根外会通过纯前缀判定）；用相对路径差判而非前缀判定（前缀判定会让 `/a/bc` 命中 `/a/b`）；判定自身出错一律拒绝（fail-closed）。
8. **工具集合从唯一事实来源派生**（ADR-0007 决策 5：同一事实不写两处），不得另抄一份。
9. **不做读写分级**：读与写用同一份允许根，不引入「可读不可写」两级模型。
10. **不做 TOCTOU 加固**：判定与实际 IO 之间的窗口不处理。威胁模型是提示注入 + 模型自发越界，不是在毫秒级窗口里抢符号链接的对手。

## Testing Decisions

两个 seam（人类已确认）：**纯函数层 + 集成层**。两者测的不是同一件事，压成一个会让边界矩阵
测试变笨重或让接线断言漏掉。

- **什么算好测试**：只测外部行为——越界调用抛出的错误内容、界内调用零行为变化。不测
  `operations` 的函数签名（那是 pi 的内部形状，会随版本漂移）。
- **纯函数层**（零 SDK 依赖）：覆盖矩阵分六类——根内（相对/绝对/`~` 展开/深层路径）、根外
  （数据库、其他成员家目录、附件目录、系统文件、家目录的兄弟目录）、前缀陷阱、符号链接
  （根内指向根外拒绝 / 指向根内放行）、不存在的目标路径（父目录 realpath + basename 回退）、
  根列表异常（空列表一律拒绝）。另覆盖注入形态（`~/` 展开、`@` 前缀裁剪、macOS 变体文件名）。
- **集成层**：守卫在位且描述未退化（断言覆盖后的定义仍带 pi 原生的提示准则——手写定义会静默丢掉
  它们，这条必须有）；合法路径零行为变化（同一文件在守卫开/关下输出一致）；reload 存活；
  **反向断言**（构造一个把根设成数据目录的假成员，断言数据库仍被拒——证明排除项是显式不变式，
  而不是「恰好不在列表里」）。
- **既有先例**：仓库用 `node:test` + `node:assert/strict`，零测试框架依赖，测试文件后缀 `.test.mjs`。
- **门禁**：`tsc --noEmit` + lint（只报告，不 `--fix`）+ `node --test`。**绝不 `next build`**。

## Out of Scope

- **bash 收口**：本设计对 bash 下的读取**不起作用**。`PRESET_DEFAULT` 档下 bash 是唯一剩余绕过面。
  收口形态未定（受限 shell / 路径重写 / 文件系统 sandbox / 收掉 bash 四种），由票 03 先做决策。
  本票不改任何工具档位的构成。
- **HITL / 审批流**：本地单人多成员场景下人在环不是当前优先级，权责划分取「隔离优先、可观测性另议」。
- **协作流里工具调用的可观测性**：当前频道消息流不渲染成员的工具调用，所以 owner 看不到成员到底
  做了什么。本票不补这个观察点（它是独立议题：涉及消息不可变约束、UI 密度、历史保留）。
- **不引入 leader / 委派 / 指派**：任务认领保持抢占语义，路径隔离与任务归属是两件事。
- **不做 TOCTOU 加固**、**不做附件的成员侧读取通路**（正确形态是经受控的附件读取通道，不是开目录）、
  **不改消息/频道/唤醒/任务语义**。

## Further Notes

- **档位差异影响「拦住了什么」的准确表述**：`PRESET_DEFAULT`（read/bash/edit/write）档下 grep/find/ls
  不可用，剩余绕过面只有 bash；`PRESET_FULL` 档下六个文件工具并列纳入才有意义，因为 grep 的读取
  能力与 read 同接缝、find/ls 会泄露目录结构。只挡三个等于交付一个执行默认「搜索一下」即可绕过的守卫。
- **术语**：「允许根」「路径守卫」已入 `CONTEXT.md` 的 `## Language`。领域词与实现词要分清——
  实现里叫「白名单」不是错，但文档正文用领域词。
- **残留下游**：协作流里 agent 的工具调用无观察点；bash 未收口。这两项在 Further Notes 记明，
  不在本票承诺。
