# 01: 任务视图滚动归属与分组折叠（实现票）

**What to build:** 修掉任务板（Tasks tab）两处滚动/布局可观察问题，分两块共四处：

- **A. Board 视图：页面本身不可滚动、列按列各自滚**——现状是外层 `main` 仍会滚，且 `.col` 靠
  `max-height: calc(100dvh - 168px)` 这条视口魔数限制高度，于是「列内滚动 + 页面滚动」两套滚动条
  同时在场的用户截图实证症状。
- **B. List 视图：工具条吸顶 + 分组可折叠 + 底部 padding**——`.board-toolbar` 现在随内容滚走；
  状态分组不可折叠；内容末尾贴底。

**Blocked by:** None — can start immediately.

**Type:** implementation

**Status:** in-progress

## Change：两块共四处可观察行为

### A. Board 视图：页面本身不可滚动，卡片按列各自滚动

1. board 视图下**页面不可滚动**：Tasks tab 的滚动只发生在列内，不发生在页面级容器上。做法自选
   （`height:100%` + flex 链、或 `min-height:0` + 内部滚动容器），但结果必须是 `.board` 自己不产生
   纵向滚动条（列高由可用高度决定），列内容超出时在 `.col-body` 内滚。
2. `.col` 的高度约束**不再用 `100dvh - 168px` 这类视口魔数**（它与实际可用高度无关：工具条、tabs 条、
   header、安全区 inset 任一变化就偏），改为跟随容器可用高度。
3. `.board-cols` 的 `align-items` 从 `flex-start` 调整为让各列等高铺满（列高一致、各自内部滚），同时
   保留「列不横向拉伸、宽度取 `--board-col-w`」这条既有断言。
4. **页面底部留足 padding**：board 的底 padding 要足够（现有 `--sp-10`），且不得因为改成等高铺满而把
   最后一列的卡片贴到视口底边或被裁掉——底部要能完整看到列底框。

### B. List 视图：工具条吸顶 + 分组可折叠 + 底部 padding

1. **顶部 new task 条吸顶**：list 视图下由 main 滚动，而 `.board-toolbar` 现在会随内容滚走。要让它像
   board 视图那样固定在顶部（`position: sticky` 或等效结构），滚动列表时始终可见。吸顶实现要能盖住
   滚上来的内容（背景不透明、有分隔线），且不遮挡首屏第一张卡片。
2. **各状态分组可折叠**：list 视图按 `TASK_STATUS_ORDER` 分组，每组标题（状态徽标 + 计数）可点击
   折叠/展开。默认展开。交互细节：
   - 折叠态要点得着、有可访问语义：用 `aria-expanded` + `aria-controls` 或等价语义；
   - 折叠时仍要能看到该状态徽标与**任务计数**（不能因为折起来就丢掉计数）；
   - 无障碍名/文案走 i18n（新增 key 落到 `en.ts` 与 `zh-CN.ts` 两个包）；
   - 折叠状态不必持久化（本票不要求写 localStorage；若顺手加了持久化，必须说明并写进 Answer，
     且不能与 `TASK_VIEW_KEY` 的现有读写分叉成第二份偏好存储）。
3. **底部 padding**：list 视图内容末尾要留出足够的底部空间（现在最后一张卡片贴底/被视口底边切到）。

## Constraints

1. **逐字搬运纪律**：`components/task-board.test.mjs` 里有一条测试断言 `app/globals.css` 的任务板规则体
   与 `worksplice-design-system/ui_kits/app/app.css` 的同名规则**逐字相同**（选择器白名单见该测试）。
   改这些同名规则的声明体（例如 `.board` / `.col` / `.board-cols` / `.col-body` / `.board-toolbar`）时，
   **必须同步改上游 app.css 的同名规则**，否则那条测试会红。**只加新 selector**（本票为 list 折叠/吸顶
   新增的 class）则不需要动上游。改了上游就在 Answer 的 Decisions 里写明「哪些规则与上游同步改了、为什么」。
2. **不新增 emoji**：UI 图标一律 lucide（仓库纪律）。折叠/展开用 lucide 现成图标（如 `ChevronDown` /
   `ChevronRight`），不要用 `▼` `▶` 之类字符当装饰。
3. **i18n key 成对新增**：`lib/i18n/messages/en.ts` 与 `lib/i18n/messages/zh-CN.ts` 必须同时加同一批
   key（有 parity 测试兜底）。key 放 `tasks.` 命名空间下。**正文用中文**（zh-CN），英文包给英文文案；
   节名/枚举值保持既有语言分层规则（见 `docs/i18n.md`）。
4. **不碰滚动之外的语义**：状态机、`reachable` 落点裁决、任务动作、卡片点击开 thread、HTML5 拖拽手势、
   NoticeToast 全部零改动。本票只动布局与折叠这一层交互。
5. **不删既有测试断言**：若某条既有断言与本票目标冲突（例如断言 `.board-cols` 的 `align-items: flex-start`、
   或断言 `.col` 的具体 max-height），**改断言并写明理由**，不许删测试换绿。既有断言清单见
   `components/task-board.test.mjs` 第 128–171 行。
6. **术语**：既有仓库术语（`board` / `col` / `stream` / `board-wrap` 等 class 名与注释）保持不动，不要
   为了架构词表去改既有注释与 class 名；新写的注释按仓库既有中文注释风格。
7. **不许改 `ChannelView` 的消息流（Messages tab）行为**：本票只影响 Tasks tab。

## Observable acceptance

1. **红绿证据（tdd，必留）**：先写断言跑一次见红，再实现见绿。绿证据必须是**产品自己渲染出的 markup**
   （`renderToStaticMarkup` + `I18nProvider`，与 `components/task-board.test.mjs` 同形），不是「class 字符串
   在源码里出现」这种实现断言。至少覆盖：
   - list 分组标题带 `aria-expanded`（默认 true）与折叠后的 `aria-expanded=false`，且两种状态下**计数都
     渲染出来**；
   - 折叠是真实交互态：用 markup 断不住「点击后展开/收起」时，用源码级断言断折叠状态的 reducer/handler
     表达式 + 两种状态下渲染出的 markup（两者结合），并在 Answer 里说明哪些是渲染证据、哪些是源码级证据；
   - board 的 sticky/等高相关 class 挂在 `.board-wrap` / `.board` / `.col` 上，且规则体里**不再出现
     `100dvh` 视口魔数**（这条可由 CSS 规则体断言机械判定）。
2. **测试档 = 宽（跑全量）**：`npm test` 期望**全绿，fail 0**。改动前基线：tests 1314 / pass 1314 / fail 0。
3. **typecheck 与 lint**：`node_modules/.bin/tsc --noEmit` 退出码 0；`npm run lint` 相对改动前零新增问题。
4. **工作流程证据链（缺一即打回）**：tdd 红→绿节奏记录；**双轴 code-review 小节**（Standards + Spec 两份
   报告，分开写不合并，findings 逐条「已改」或「豁免 + 理由」）；**换 prop / 换字段清点**（列出新 prop 的
   全部出现位置并逐个标注「改了 / 故意不改 + 理由」）；**同票内同类操作同形**（list 分组折叠标题与 board
   列头都是「状态 + 计数」的表头，两处若形态不一致必须解释）；约束 5 若动了既有断言，逐条列出改了哪条、
   为什么。
5. **交付物持久化**：推分支 + `gh pr create`，PR 号回填 Answer。
6. **工作区干净**：交付前 `git status --porcelain` 为空（`.pi-lens.json` 已被 exclude）；`git diff --numstat`
   只有真正改的少量行。
