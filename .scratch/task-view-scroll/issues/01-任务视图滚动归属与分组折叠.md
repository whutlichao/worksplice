## Change：两块共四处可观察行为

### A. Board 视图：页面本身不可滚动，卡片按列各自滚动

1. board 视图下**页面不可滚动**：Tasks tab 的滚动只发生在列内，不发生在页面级容器上。做法自选
   （`height:100%` + flex 链、或 `min-height:0` + 内部滚动容器），但结果必须是 `.board` 自己不产生
   纵向滚动条（列高由可用高度决定），列内容超出时在 `.col-body` 内滚。
2. `.col` 的高度约束**不再用 `100dvh - 168px` 这类视口魔数**（它与实际可用高度无关：工具条、tabs 条、
   header、安全区 inset 任一变化就偏），改为跟随容器可用高度。
3. `.board-cols` 的 `align-items` 从 `flex-start` 调整为让各列等高铺满（列高一致、各自内部滚），同时
   保留「列不横向拉伸、宽度取 `--board-col-w`」这条既有断言。
4. **页面底部留足 padding**：board 的底 padding 要足够（现有 `--sp-10`），且不得因为改成等高铺满而把
   最后一列的卡片贴到视口底边或被裁掉——底部要能完整看到列底框。

### B. List 视图：工具条吸顶 + 分组可折叠 + 底部 padding

1. **顶部 new task 条吸顶**：list 视图下由 main 滚动，而 `.board-toolbar` 现在会随内容滚走。要让它像
   board 视图那样固定在顶部（`position: sticky` 或等效结构），滚动列表时始终可见。吸顶实现要能盖住
   滚上来的内容（背景不透明、有分隔线），且不遮挡首屏第一张卡片。
2. **各状态分组可折叠**：list 视图按 `TASK_STATUS_ORDER` 分组，每组标题（状态徽标 + 计数）可点击
   折叠/展开。默认展开。交互细节：
   - 折叠态要点得着、有可访问语义：用 `aria-expanded` + `aria-controls` 或等价语义；
   - 折叠时仍要能看到该状态徽标与**任务计数**（不能因为折起来就丢掉计数）；
   - 无障碍名/文案走 i18n（新增 key 落到 `en.ts` 与 `zh-CN.ts` 两个包）；
   - 折叠状态不必持久化（本票不要求写 localStorage；若顺手加了持久化，必须说明并写进 Answer，
     且不能与 `TASK_VIEW_KEY` 的现有读写分叉成第二份偏好存储）。
3. **底部 padding**：list 视图内容末尾要留出足够的底部空间（现在最后一张卡片贴底/被视口底边切到）。

## Answer

### 一句话

看板视图的列高不再跟视口走（`max-height: calc(100dvh - 168px)` 退场），改由容器可用高度决定：页面级纵向滚动退场、卡片超出时在 `.col-body` 内滚，各列等高铺满且列底框完整可见；列表视图的工具条改为吸顶（`.board-wrap` 在该视图退回 `overflow: visible`，让 `main` 成为滚动容器），状态分组标题变成可折叠的按钮（`aria-expanded` + `aria-controls`，折叠态徽标与计数仍在），内容末尾留出 `--sp-12` 的底部空间。

### 根因（用户截图症状的机械解释）

`.col` 的 `max-height: calc(100dvh - 168px)` 与实际可用高度无关：`100dvh - 168px` 减掉的只是「header + tabs + 工具条」的一个**常数估计**，而真实占用是动态的（描述行有无、可折叠面板开合、`env(safe-area-inset-*)`、横向滚动条本身还要占 9px）。本机实测该差值约 **+25px**：列永远比可视区高一点 ⇒ `.board`（`overflow: auto`）与 `.col-body`（`overflow-y: auto`）**同时**出现滚动条，正是截图里的两条。修法不是把 168 调准（换个数照样偏），而是让列高跟容器走：`.board-cols` 的 `align-items: stretch` + `height: 100%`，`.col` 只留 `min-height: 0`，`.col-body` 用 `flex: 1` 吃满剩余列高。

### Decisions

**1. 与上游 `worksplice-design-system/ui_kits/app/app.css` 同步改了哪三条、为什么**（约束 1）：

| 规则 | 改动 | 为什么必须同步 |
| --- | --- | --- |
| `.board-cols` | `align-items: flex-start` → `stretch`；新增 `height: 100%` | 票面 A3 明写要改这条；它在那条「逐字搬运」断言的白名单里，只改本仓会让断言当场变红 |
| `.col` | 删 `max-height: calc(100dvh - 168px)`；加 `min-height: 0` | 票面 A2 明写视口魔数退场；`.col` 同样在白名单里 |
| `.col-body` | 加 `flex: 1`（列内滚的前提：列体吃满列高） | A1 的「列内容超出时在 `.col-body` 内滚」要求列体先占满剩余高度；同样在白名单里 |

另外**同文件一处非白名单改动（已登记）**：`@media (max-width: 900px)` 段里 `.board-cols { flex-direction: column; }` → 补 `height: auto;`，`.col { … max-height: none; }` → 删掉那句 `max-height: none`。理由：基础规则里 `max-height` 已不存在，`max-height: none` 成了悬空声明；而新加的 `height: 100%` 在窄屏单列堆叠下会让 5 列各占满屏高，所以补 `height: auto` 收口。**本仓 globals.css 没有这条媒体查询**（它只搬那批被白名单覆盖的规则），所以这条改动只影响设计套件自身的原型、不影响产品；白名单断言也不覆盖它，属于「同步契约之外的收口」，一并登记在此。

**未改的**：`worksplice-design-system/worksplice-app.html`（第 280 行仍是 `max-height:calc(100dvh - 168px)`）。它是设计系统的**主证据产物**（Open Design 原型单文件），不在本票 Ownership 内，且本仓对这类历史快照的既有纪律是「历史事实原样保留」（先例：历次票据对 `.scratch/` 旧调研快照的处理）。⇒ 登记为遗留项，由后续清理票决定是否加 provenance 备注。

**2. 折叠状态放哪、要不要持久化**：放 `TaskViews` 而不是 `TaskList`——两个视图切换时 `TaskList` 会卸载，状态放它身上会在切看板再切回列表时静默丢折叠；`TaskViews` 常驻，折叠态跨视图保留（真浏览器实测：折叠「待认领」→ 切看板 → 切回列表，`aria-expanded` 仍是 `false`）。**不持久化**：折叠是会话内的阅读态而非偏好，票面 B.2 也未要求；因此 `localStorage` 的写入面保持只有 `TASK_VIEW_KEY` 一个（测试用「写入面清点」把这条锁成机械事实，而不是靠「没写某个新键」的否定断言）。

**3. 折叠的 DOM 形态**：组体**留在 DOM 里**并置 `hidden`，而不是条件渲染。理由：`aria-controls` 指向的元素必须始终存在（目标消失是 a11y 反模式），且展开/收起只翻一个属性、无重挂载。这里**不需要**为 `.task-group-body` 再写一条 `[hidden]` 规则——本仓 reset 里已有 `[hidden] { display: none !important }`（`app/globals.css:42`，与上游 `app.css:34` 同款），`!important` 压得住 `.task-group-body` 自己的 `display: flex`；测试改为把这条 reset 当成**承重件显式登记**（它一没，折叠会静默失效）。该结论由 Standards 轴 review 逼出来（初版多写了一条冗余规则、注释还把成因归于 UA 样式，已删）。

**4. 列表分组头与看板列头的形态差异（同票内同类操作同形，票面要求解释）**：两处**都是**「状态 + 计数」的表头，但形态不同，逐个说清是谁引入的：

| 维度 | 看板列头（`.col-head`，本票未动） | 列表分组头（`.task-group-head`，本票新写） |
| --- | --- | --- |
| 状态表达 | `.st-dot` 状态点 + `<b>` 文本 | 状态**徽标**（`taskBadgeStyle`，填充档底 + 深墨字） |
| 计数表达 | `.col-count` 胶囊（`--surface` 底 + 描边 + `--r-pill`） | `.task-group-count` 裸 mono + `--faint` |
