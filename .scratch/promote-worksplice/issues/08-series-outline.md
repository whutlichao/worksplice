## Question

Q11 已定主轴：**问题场景做骨架、机制做里子**。现在要定 4–6 周的具体选题与取材：

- 每篇讲哪个**问题场景**（「两个 agent 抢同一个文件」、「谁来宣布这件事做完了」、「被唤醒的 agent 怎么知道自己错过了什么」、「为什么不能让 agent 自己验收」……），挂到哪个**机制里子**（freshness-hold / 互审状态机 / wake + cursor / 重开封锁）。
- 里子从哪来：`docs/design-notes/orchestrating-coding-agents.md`（2.1 万字库存）怎么拆成多篇；05 的实测证据文排在第几周；哪些篇目需要新写、新写的工作量。
- 每篇**发在哪**：英文（pi Discord / GitHub / 掘金改写？）与中文的对应关系；同一篇要不要两个语言版本。
- 哪些篇目需要额外素材（架构图、hold 的原始 payload、任务板截图、成本数字）。
- **哪些篇目可以顺手覆盖「同行对比」**（把 02 定的对比口径落进具体一篇，而不是单独发一篇对比文——landscape 明确「对比叙事在渠道上是资产，在流量上不是」）。

**产出**：6（或 4）行选题表：周次 → 问题场景 → 机制里子 → 首发渠道 → 语言 → 需要的新素材 → 是否已有库存。

## Answer

2026-10-03 谈定。**5 周**；每篇 = **仓库长文 + Discord 短帖引流**（Discord 单条上限 2000 字符，长文放不下）；**掘金改写 W2 与 W4 两篇**；示意图我做、成本数字你导。

### 2. 渠道映射（与票 07 的日历对齐）

- **pi Discord**：每周一条短帖（W1 是自包含长帖＋续帖）——它承载节奏，不承载长文。
- **仓库 `docs/design-notes/`**：每篇长文的正本（可被引用、可被搜索）。W2 已是正本；W3/W4/W5 从主打长文拆章后独立成文。
- **掘金**：W2、W4 两篇改写成中文技术文（官方罚则要求纯技术文形态，这两篇最对口）。
