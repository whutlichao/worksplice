# 03 — 90 秒录屏：分镜与可直接照录的脚本

**Type:** prototype
**Blocked by:** 02
**Status:** resolved

**输入（来自已关闭的 [02 首发消息面](./02-launch-message.md)）**：主体 = 并发写裁决（两个 agent 基于同一房间版本写 → 第二个被 hold → revise）；开场 30 秒借「构建者不验证」的任务板 + 互审画面交代「这是什么」，后 60 秒用真实 hold 现场交代「凭什么可信」。分镜按这个分工设计。

**输入（来自已关闭的 [04 一行安装](./04-one-line-install.md)）**：`--demo` 已定提前到首发，它会提供一套**可重复、零成本、不需要模型 key** 的演示现场（5 agent / 4 频道 / 40 消息 / 14 任务）——大部分镜头可以直接在这个现场上录，只有「hold 现场」必须真跑（见票 05）。分镜要写清哪些镜头用 `--demo`、哪些必须真跑。

## Question

Q7 已定先做 README 顶部的 90 秒录屏、再做 Release。要定的是：

- 90 秒里观众依次看到哪几幕（哪一幕承担「这是什么」，哪一幕承担「凭什么可信」）。
- 用**真实 agent 跑**（可信但慢、依赖模型 key）还是用 **`seed:demo` 数据**（秒级、可重复、零成本）——还是两者混用。
- 字幕还是旁白；画面里要不要出现终端。
- 结尾把观众导向哪里（pi Discord？GitHub Release？README 的 Quick Start？）。

**产出**：逐镜头脚本（每镜头：画面、演示数据准备、操作顺序、屏幕文字）+ 一份「照着就能录」的操作清单。landscape 样本里 demo 视频只有 3/12，但**截图是常态**（emdash 7 张、superset 8 张、claude-squad 4 张；worksplice 现有 4 张）——脚本要顺带定下还要补哪几张静态截图。

## Answer

2026-10-03 谈定。分镜对着现有截图的真实像素设计（`docs/screenshots/channel.png` / `task-board.png`）。**90 秒 / 10 镜 / 纯字幕（无旁白）/ 16:9。**

### 0. 一条决定骨架的事实

**hold 在 UI 里不可见。** `round_logs` 只在 agent 面板里显示「轮次结论」，而成功 revise 与普通回复同为 `replied`（连 `reason` 都是空的）。所以核心那 60 秒不能靠任何界面元素说服人，只能靠两样东西：**她回复的正文**（明确回应了打断她那句）＋ **她会话文件里的 revise prompt 原文**。这是设计选择，不是妥协。

### 1. 分镜

| # | 时间 | 画面 | 字幕 |
| --- | --- | --- | --- |
| 1 | 0:00–0:06 | 冷开场：任务板全景（stream-sync → Tasks → **Board**），5 列都在 | 五个 agent。一个仓库。谁说了算？ |
| 2 | 0:06–0:16 | 横移到 `In review` 列，停在一张卡上（`#4 add a settled_at field…`），露出 **Approve / Reject** | 完成不等于通过——批准按钮只对**不是他**的人有意义 |
| 3 | 0:16–0:26 | 切 `Messages`，缓慢滚动一周的对话（引用块、@提及、表情聚合） | 不是聊天记录。是工作本身。 |
| 4 | 0:26–0:34 | 打开 Iris 的 agent 面板：状态点、workspace、模型、token/成本、任务历史 | 每个 agent 是一条持久身份：自己的目录、自己的模型、自己的成本账 |
| 5 | 0:34–0:44 | **真跑**：Bob 发出唤醒消息，侧栏 Alice 的状态点转黄脉冲 | 她被唤醒了。唤醒只带一个位置指针，不带正文。 |
| 6 | 0:44–0:50 | **趁她写作**，Bob 补第二条：「引号里的逗号会被切坏，先说方案」 | 房间在她写作时变了。 |
| 7 | 0:50–1:04 | 她的回复出现，正文明确回应了第二句（「收到，引号内逗号这点我原来的方案漏了…」），高亮 | 她的写没有被合并，也没有覆盖——它被拒绝了。她重读、重写。 |
| 8 | 1:04–1:16 | 会话文件里的 revise prompt 原文（滚到关键三行：`was held because the room changed while you were writing` / `What happened: 2 new message(s) arrived (seq 4–5)` / `Your held draft was:`） | 这不是 UI 特效。这是她的会话文件。 |
| 9 | 1:16–1:26 | README 的匿名对照表 5 行 | last-write-wins 是默认。我们没有默认。 |
| 10 | 1:26–1:30 | 收尾卡：一行安装命令 + 仓库地址 | `npx --yes <release 资产 URL>` |

**哪些镜必须真跑**：5–8（第 8 镜的素材就是真跑的副产物）。1–4、9、10 用 `--demo`（可重复、零成本、随时重录）。

### 2. 录制 recipe（照着就能录）

**前提**（都是已定但尚未完成的执行项）：① [PR #67](https://github.com/whutlichao/worksplice/pull/67) 已合并；② `--demo` 已实现；③ `v0.1.0` Release 已挂 tarball 资产（第 10 镜的命令行）。

**环境**：两个实例——`--demo` 实例（镜 1–4、9）＋ 真跑实例（镜 5–8；一次性项目目录 + 一个 agent，做法见 [05 的脚本](../evidence/part-b-real-run.sh)）。浏览器固定 1920×1080、隐书签栏、系统通知静音；账号头像与昵称先改成可公开的（不要出现本机用户名）。

**第 6 镜的时机**（唯一容易录砸的地方）：**不要掐秒表**。用票 05 的做法——轮询她的 session，等 `[worksplice:target=<频道> seq=N]` 出现（= 她真的 drain 完），再发第二条；插话前把该频道静音，避免新消息唤醒她又起一轮（静音只挡唤醒，不影响 hold 与 revise 读到新正文）。

**重录策略**：免费模型会自己塞 task 操作（→ `yielded`）或选 `anyway`，预留 **3 次重跑**的时间与干净数据目录；不剪接、不伪造。

### 3. 要补的静态截图（现有 4 张已覆盖 channel / task-board / agent-panel / search）

2. **对照表图**——README 那 5 行匿名对照表做成一张卡片；用于 Discord 长帖与掘金文。
3. （可选）**一行安装的终端图**——`npx --yes …` 跑出来的输出。

- **`part-b-session.jsonl` 不得入镜**：它内嵌 agent 系统提示里的本机技能绝对路径。第 8 镜只用 `part-b-revision-prompt.txt`——已逐字检查，**不含任何本机路径**，可直接公开。
- 现有截图是 1970×989（≈2:1），录制按 1920×1080 取景时注意左右留白，别把三栏骨架裁掉。
- 第 2 镜只**悬停** Approve/Reject，不真点——点了会改演示数据的状态。
