# 02: DM 回应判断（确定信号）

**What to build:** DM 内 owner 发出的人类消息是确定信号，agent 必须回应；agent 回复 ignore 按失败处理（不 ack、error 状态点、连续 2 次后 cap-ack 兜底）；DM 内 agent 自己的消息与系统事件沿用既有跳过规则。

**Blocked by:** 01

**Status:** resolved

- [x] DM target 下作者为 owner 的人类消息被判定为必须回应（must-respond）
- [x] ignore 按失败处理：不推进游标、error 状态点、消息保持 pending 供重试
- [x] 连续 2 次 ignore → cap-ack 兜底，可见 error
- [x] DM 内 agent 自己的消息、系统事件不重复应答
- [x] agent-loop 测试（fake runtime 注入）覆盖上述

## Answer

### 实现决策

1. **DM 确定信号接入既有 must-respond 路径**（`lib/agent-loop/loop.ts`）：`hasMustRespondSignal` 新增一条——`isDM(targetId) && incoming 里有 author_id === OWNER_MEMBER_ID 的消息`。drain 的 author 过滤（`incoming = drained.messages.filter(author_id !== agent.id)`）已把 agent 自己的消息挡在 incoming 之外，故 DM 内 incoming 里的 owner 消息即真实人类私信；reminder 系统事件（agent 署名）也被同一过滤挡掉，不构成确定信号。ignore 失败 / cap-ack 全部复用既有机制（`MUST_RESPOND_FAILURE_CAP=2`、`recordMustRespondFailure`/`resetMustRespondFailures`、error 状态点、不 ack）。
2. **rubric 增补**（`buildReplyPrompt`）：仅当 `channel.type === "dm"` 时追加一条 DM rule——"this channel is your direct message with the owner — a human message from the owner here is always a MUST reply; ignoring it is treated as a failure"，让 decide 的 prompt 与 must-respond 判定同源（避免模型在 DM 里自判 ignore 后又被判定失败）。
3. **作用域只限 DM channel 主流程**：`isDM(targetId)` 仅对 channel target 为真（thread 锚点是消息 id，非频道），故 DM 内任务线程仍走既有 thread 规则（@mention / in_progress task owner），符合 spec R4 "DM target 下"与"任务线程自醒在 DM 内同样适用"。drain/ack/游标机制零改动。
4. **顺带补一处 SAFETY 注释**：pi-lens 对编辑文件做整文件自扫，loop.ts 既有 `waitForCwdSettle(waitTarget as unknown as SettleableSession)`（HEAD 已存在、非本票引入）被标为 blocker——补一行 SAFETY 注释说明 LoopSession 结构满足 SettleableSession 的逆变安全（纯注释，无行为改动）。

### Review

**Spec 轴（对照票据 02 验收标准逐条）**：

1. ✅ DM target 下 owner 人类消息 = must-respond（`hasMustRespondSignal` DM 分支；测试「a DM owner human message is a must-respond signal: ignore fails without ack」）
2. ✅ ignore 按失败处理：不推进游标、error 状态点、消息 pending 供重试（复用既有失败路径；测试断言 `getConsumedSeq === 0` + `status === "error"`）
3. ✅ 连续 2 次 ignore → cap-ack 兜底、可见 error（`MUST_RESPOND_FAILURE_CAP=2`；测试「consecutive DM ignores cap at 2 then ack with error」断言第二次 `(capped at 2)` + 游标推进到 1 + error 状态）
4. ✅ DM 内 agent 自己消息/系统事件不重复应答（测试「the agent's own DM message does not trigger a repeated response」→ noop、「an agent-authored system event (reminder) in the DM is not a must-respond signal」→ ignored 非 error）
