# 01: DM 通道地基与成员规则

**What to build:** 每个 agent 拥有一条 `type='dm'` 的一对一私信通道，成员创建时定死为 owner + 1 个 agent；DM 上禁止加人、退订、归档、离开、静音、改名；存量 agent 幂等补齐、新建 agent 同步建；agent 软删除后 DM 保留可读、不可写。

**Blocked by:** 无（可立即开始）

**Status:** resolved

- [x] 频道类型支持 `dm`（CHECK 扩展 `('public','private','dm')`），schema 版本 +1，老库迁移兼容且可重跑
- [x] 创建 DM 幂等：同一 agent 重复创建返回既有 DM，不产生第二条
- [x] DM 成员恒为 owner + 1 agent，创建时定死
- [x] join / leave / archive / mute / 改名 对 DM 一律拒绝（服务层抛错）
- [x] 存量 agent 幂等补齐 DM；新建 agent 时同步建 DM（与自动加入 `#all` 同处）
- [x] agent soft-delete 后其 DM 保留可读、不再可写
- [x] 服务层测试覆盖上述全部行为

## Answer

### 实现决策

1. **DM id 生成规则**：确定性命名 `dm:owner↔<agent名>`（`DM_ID_PREFIX = "dm:owner↔"` + agent 名，spec R7），id == name。确定性天然幂等——同一 agent 重复 `createDirectChannel` 命中既有行直接返回；迁移补齐用 `INSERT OR IGNORE` 可重跑。**已知边界**：同名 agent 软删后重建会复用同一条 DM（含历史），且旧 DM 已归档只读——本票按 spec R7 名称命名落地，此边界记录在案（后续票如需"重建即新 DM"再议）。
2. **CHECK 迁移（v11→v12）**：SQLite 无法 ALTER 改 CHECK，用 expand-contract——`foreign_keys=OFF` + `legacy_alter_table=ON`（RENAME 时不改写指向 channels 的外键，否则引用会漂到 channels_old 而悬空）→ RENAME channels→channels_old → 建新表（CHECK 含 'dm'）→ 拷贝 → DROP。放在 `runMigrations` 事务外（PRAGMA 事务内 no-op），且先于 seed 的 DM 补齐执行。检测建表 SQL 含 `'dm'` 即跳过（幂等可重跑）。
3. **服务层窄入口**（`lib/domain/raft/channels.ts`）：`createDirectChannel` / `isDM` / `getDMFor`（+ 私有 `directChannelId`、`assertNotDM` 守卫）。`joinChannel` / `leaveChannel` / `setChannelArchived` / `muteChannel` / `unmuteChannel` 开头加 `assertNotDM` 拒绝；`createChannel` 拒绝 `type='dm'`（只能走 `createDirectChannel`）。"改名"：仓库无改名 API，trivially 满足（无需守卫）。
4. **成员生命周期**：`createAgent` 在自动加入 `#all` 之后同步 `createDirectChannel`；`deleteAgent` 在事务内把 DM 归档（`setChannelArchived(dm, 1)`，复用 `sendMessage` 的 archived 只读语义 → "保留可读、不可写"）；seed 对未删 agent 幂等补齐 DM。
5. **秘书覆盖**：`initSecretaryFlow` 频道覆盖循环跳过 `type='dm'`（秘书只在自己 DM 内、不加入他人 DM）。
