# 04: DM 功能面（任务/提醒/搜索/未读复用）

**What to build:** DM 内任务、提醒、搜索、未读全链路复用既有机制；任务 number 按 DM 内递增、互审另一方只能 Owner；提醒可锚定 DM 消息并到点唤醒作者。

**Blocked by:** 01, 03

**Status:** resolved

- [ ] DM 消息可转任务，number 按 DM 内独立递增
- [ ] 任务状态机在 DM 内可用；approve / reject（互审）另一方只能是 Owner
- [ ] 提醒可锚定 DM 消息，到点触发系统消息 + 唤醒作者
- [ ] 搜索命中 DM 消息、DM 计入未读
- [ ] route + 服务层测试覆盖

## Answer

### 实现决策

本票为「验证复用 + 补 DM 特判 + 测试」，唯一需要改代码的是互审语义（经 orchestration ask 问回，coordinator 决策 A）：

- **DM 互审特判（唯一代码改动）**：`lib/domain/raft/tasks.ts` 新增私有 helper `isTaskInDM(task)`（读锚点消息 → `getChannel(...).type === "dm"`，锚点/channel 缺失防御性兜底按非 DM 处理），`reviewAuthorized` 加前置判断——DM 内 approve/reject **仅人类 Owner（CURRENT_MEMBER_ID）可做**，agent 永不当审核者。据此：agent 建任务 complete→in_review 后由 Owner 审；Owner 建任务走人类豁免自审。`updateTaskStatus` 的 in_review 越权分支补 DM 专属错误消息 `"In a DM, only the owner can approve or reject tasks"`。`reachableStatuses` 经 TRANSITIONS 表自动携带该特判（无需额外改动，测试已锁定）。
- **复用确认（零代码改动，仅测试锁定）**：任务 `createTask` 已按 channel 递增 number（DM 是 channel，天然生效）、thread 内不可转的校验对 DM 顶层消息同样成立；提醒 `resolveChannelForTarget` 已把 DM（channel）归一化，`scheduleReminder` 作者成员校验 + `fireReminder` 系统消息投递 + 定向唤醒作者对 DM 天然成立；搜索 `searchMessages` 是 FTS 全表、结果附 channel 归属（DM 经 `resolveChannelForTarget` 解析）；未读 `listChannelsWithMeta`/`unreadCount` 已对 DM 计未读（03 已确认零改动）。
