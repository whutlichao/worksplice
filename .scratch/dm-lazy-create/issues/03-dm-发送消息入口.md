## 实施指路

1. **route**（`app/api/members/[id]/dm/route.ts`，薄封装）：`POST` → `createDirectChannel(id)`（幂等，服务层已实现）→
   返回 `{ channel }`（附 meta，供 AppShell 合并）；`getAgent` 先校验 agent 存在且未软删（`createDirectChannel` 对
   软删 agent 会复用已归档的 DM——route 层用 `getAgent` 拦掉软删，404）。错误路径：`AgentNotFoundError` → 404，其余 500。
2. **AgentDetailPanel 按钮**（`components/AgentDetailPanel.tsx`）：身份头正下方加醒目主按钮（`var(--yellow)` 底、
   lucide `MessageSquare` 图标，与侧栏 DM 图标一致）。文案动态：`getDMFor` 语义——无 DM 或无消息 →「发送消息」，
   有消息 →「打开私信」。判定「有无消息」复用 02 的信号（可经 observability 数据或轻量 fetch，实现自选，避免 N+1：
   优先让 route `POST /api/members/[id]/dm` 返回 `{ channel, hasMessages }`，按钮据此定文案，点击时再幂等创建）。
3. **AppShell 接线**：`AgentDetailPanel` 增 prop `onOpenDM(channelId: string)`；`DetailPanel` 透传；`AppShell`
   实现——调用 `POST /api/members/[id]/dm` → 把返回的 channel 合并进 `channels`（参照 `load()` 的 merge 逻辑，保持
   行引用稳定，避免 ChannelView loader 重建）→ `handleSelectChannel(channel.id)` → 再 `setPanelContent(null)` 关闭
   右栏面板（**不要**改 `handleSelectChannel` 本身——它被普通频道行点击共用，不关面板）。
4. **聚焦 composer**：导航到 DM 后聚焦输入框（ChannelView 已有 composer，加聚焦机制——如 `centerSelection` 变化后
   focus，或给 ChannelView 传 `autoFocus` 标志；实现自选，别引入跨组件耦合）。
5. **i18n**：`lib/i18n/messages/{en,zh-CN}.ts` 加 `agent.sendMessage`（发送消息 / Send message）与
   `agent.openDM`（打开私信 / Open DM）。
6. **测试 seam**：`components/AgentDetailPanel.test.mjs` 渲染断言按钮文案动态 + 点击触发 `onOpenDM`；
   `app/api/members/[id]/dm` 的 route 源码级断言（幂等建/取、软删 404）。
