## Answer

**实现决策**

- **route**（`app/api/members/[id]/dm/route.ts`，薄封装）：`POST` → 先 `getAgent(id)` 拦软删/不存在/非 agent（`AgentNotFoundError` → 404），再 `createDirectChannel(id)`（服务层幂等、成员定死）；返回 `{ channel, hasMessages }`——`channel` 经 `listChannelsWithMeta(CURRENT_MEMBER_ID)` 附 meta（joined/memberCount/unread/messageCount）供 AppShell 合并，`hasMessages = messageCount > 0`。route 不重复实现业务规则。
- **AgentDetailPanel 按钮**：身份头正下方醒目主按钮（`var(--yellow)` 底 + lucide `MessageSquare`，与侧栏一致，未新增 emoji）；文案动态——`hasMessages` prop 决定「发送消息」/「打开私信」；点击 `onOpenDM(agent.id)` 上抛。
- **AppShell 接线**：`AgentDetailPanel` 增 `onOpenDM(agentId)` prop → `DetailPanel` 透传 → `AppShell.handleOpenDM`（`POST /api/members/[id]/dm` → merge 进 channels（参照 load() merge 语义，保持行引用稳定）→ `handleSelectChannel(channel.id)` → `setPanelContent(null)` 额外关右栏面板 → `setComposerFocusSignal(n+1)`）。未改 `handleSelectChannel` 本身（普通频道行共用）。
- **聚焦 composer**：`Composer` 增 `focusSignal?: number` prop，`useEffect` 变化时 `textareaRef.focus()`；经 ChannelView `composerFocusSignal` 透传。普通频道行点击无信号不触发。
- **i18n**：`agent.sendMessage`（发送消息/Send message）+ `agent.openDM`（打开私信/Open DM）双语。
- **`hasMessages` 判定**：AppShell `dmHasMessages` 复用 02 的 `messageCount` 信号——确定性 id `dm:owner↔<agent名>`（`DM_ID_PREFIX`）在 `channels` 里找 DM，`messageCount > 0` 即有消息。**顺带修复 02 遗留的 merge 缺口**：`shallowEqualChannel` 原不含 `messageCount`，新消息入流后侧栏 DM 分组与按钮文案会冻结在旧值——补入 `messageCount` 比较 + 15s 轮询同步 `messageCount`（02 的 Answer 已明确此接线归 03 票）。
