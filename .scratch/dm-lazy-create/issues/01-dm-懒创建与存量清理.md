## 实施指路

1. **移除 eager 创建**（`lib/domain/raft/members.ts`）：删 `createAgent` 末尾的 `createDirectChannel(agent.id)` 调用；
   若 `createDirectChannel` import 不再被本文件使用则一并删 import（`getDMFor` 仍被 `deleteAgent` 使用，保留）。
2. **移除 seed §R6**（`lib/data/schema.ts` `seed()`）：删掉 §R6 三段 DM `INSERT OR IGNORE`（channels / owner member /
   agent member）。`DM_ID_PREFIX` 常量仍被 `channels.ts` 的 `directChannelId` 使用，保留。
3. **幂等清理空 DM**（`lib/data/schema.ts` `runMigrations()`）：事务内（seed 之后）加一段
   `DELETE FROM channels WHERE type='dm' AND id NOT IN (SELECT DISTINCT target_id FROM messages)`，
   再删这些 channel 的 `channel_members` 关联行（`DELETE FROM channel_members WHERE channel_id IN (SELECT id FROM channels WHERE type='dm' AND id NOT IN (...))`）。
   无 schema 形状变更，**不 bump SCHEMA_VERSION**；每开库幂等执行，顺带自动回收「点开未发」的空 DM。
   「空」判定 = 无任何 `target_id = dm.id` 的顶层消息（DM 首条消息必为顶层，故「无顶层消息」⟺「无消息」）。
4. **deleteAgent 兼容**（`lib/domain/raft/members.ts`）：`deleteAgent` 里 `if (dm)` 已可选，无需改代码；
   补测试锁定「懒创建下无 DM 的 agent 删除不炸、不误归档他人 DM」。
5. **测试 seam**：`lib/domain/raft/dm.test.mjs` 或新测试文件——数据层直插 agent（绕过 createAgent）验证
   `createDirectChannel` 本身仍幂等；`createAgent` 不再建 DM；迁移删空 DM 幂等；`deleteAgent` 无 DM 不炸。

## Answer

### 实现决策

1. 移除 eager 创建：`members.ts` 删掉 `createAgent` 末尾的 `createDirectChannel(agent.id)` 及对应 import（`getDMFor` 仍被 `deleteAgent` 使用，保留）。
2. 移除 seed §R6：`schema.ts` `seed()` 删除三段 DM `INSERT OR IGNORE`；`DM_ID_PREFIX` 保留（仍被 `channels.ts` 的 `directChannelId` 导出使用）。
3. 幂等清理：`schema.ts` 新增 `cleanupEmptyDms()`，在 `runMigrations()` 事务内 seed 之后执行，不 bump `SCHEMA_VERSION`。空判定 = 无 `target_id = dm.id` 的顶层消息（与票 02 的「有消息」信号同源）。
   **对实施指路的必要修正**：除 `channel_members` 外，还清理了 `channel_reads` / `channel_mutes` / `pinned_messages` 三张引用 `channels(id)` 的表。原因是「点开未发」的空 DM 会被 `markChannelRead` 写入 `channel_reads` 行（读游标=0），若只删 `channel_members` 再删 `channels`，外键约束会阻断 DELETE、整个开库事务回滚。补齐后「顺带回收点开未发的空 DM」这一票面目标才真正成立。SQL 逐表写死（不拼表名），规避动态 SQL 注入告警。
4. `deleteAgent` 无需改代码（`if (dm)` 已可选）；补测试锁定。
