# 02: Task 锚点显示总回复数并独立刷新未读数

**What to build:** 主频道 Task 锚点上的讨论入口显示该 thread 的总回复数，同时以独立的“未读 N”表达未读回复数。总数不含锚点、包含所有作者的回复且不受已读位置影响；入口始终可用，零回复显示 `0`。新回复后，两个 Task 计数都在频道可见时按现有 3 秒节奏更新，即使没有新的频道顶层消息。无障碍名称清楚区分 Task 编号、总回复数、未读回复数和打开讨论动作。

**Blocked by:** None — can start immediately.

**Type:** implementation

**Status:** ready-for-agent

- [ ] Task 锚点主数字统计所有 thread 回复（含 Owner 回复），不含锚点，已读状态不会减少总数。
- [ ] 总回复数之外独立呈现精确的“未读 N”；未读仍按该 Task 自己的已读位置与现有作者规则计算。
- [ ] 讨论入口始终存在，零回复时显示总数 `0`，并能打开对应 Task thread。
- [ ] Task 回复变化后，在频道可见时不晚于下一个 3 秒刷新周期更新总数与未读数；即使频道顶层序列不变也会更新，浏览器后台遵循现有暂停刷新行为。
- [ ] 无障碍名称分别说明 Task 编号、总回复数、未读回复数和打开讨论动作，不将总数读成未读数。
- [ ] 既有 Task 未读游标、侧栏未读 Task 数、未读总览/筛选和标读规则保持不变；普通消息 thread 计数刷新行为不变，Task View 卡片不新增总数。
- [ ] 测试验证产品渲染出的计数、按钮语义与无障碍名称，以及只有 Task thread 回复变化时的刷新；不以 CSS class 字符串替代用户可观察行为断言。

## Comments

- 拆票决策（人定）：用户选择一张端到端实施票，无前置票；同一票交付总数/未读分离、刷新与验证，避免先交付一个仍缺自动刷新的中间状态。
