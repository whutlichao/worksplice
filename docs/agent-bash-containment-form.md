# agent 的 bash 收口形态（决策文档）

**状态**：形态已定（候选 3：文件系统层沙箱），待实施票。
**口径说明（第 2 轮）**：形态本体由第 1 轮人类拍定（候选 3 + HTTP 走廊的排序链）。形态内部的四条政策里，前三条——allow-only / 用户级凭证不进清单 / 沙箱跟随会话归属的成员——**人类已拍板（2026-10-06）**；第四条（非 macOS 姿态 fail-closed）**待人类追认**，且那一条是 **coordinator 代答而非人类拍板**（代答理由见表下注）。该条触及产品能力面（非 macOS 平台的成员将没有 bash），实施票开工前需人类确认。

**关联**：ADR-0012（本票新增，bash 收口形态）、ADR-0011（文件工具的路径边界）、ADR-0001（家目录与共享项目目录）、ADR-0007（SDK 委托边界）、ADR-0008（分层与深模块）、`.github/SECURITY.md`（既有暴露面口径）。

## Problem Statement

票 02 把六个文件工具（`read` / `write` / `edit` / `grep` / `find` / `ls`）收进允许根之后，`bash` 是**唯一剩余的绕过面**：`PRESET_DEFAULT`（`read` / `bash` / `edit` / `write`）档下它是全部，`PRESET_FULL` 档下它与六个文件工具并列。`cat ~/.worksplice/worksplice.db` 对它毫无阻力——数据库、附件目录、其他成员的家目录整片可达。

**bash 与文件工具的关键差别，决定了本票不能照抄票 02 的收口办法**：

| | 文件工具 | bash |
| --- | --- | --- |
| 守卫拿到的输入 | **已经解析好的绝对路径**（ADR-0011 D1 逐工具取证：`read.js:73` / `write.js:31` / `edit.js:94` / `grep.js:57` / `find.js:65` / `ls.js:40` 都是先解析再碰 `ops.*`） | **整条命令字符串**（`dist/core/tools/bash.js:261` 是 `ops.exec(command, cwd, {...})` 的唯一调用点，`cwd` 是会话目录，命令本身没有被解析过） |
| 越界行为发生在哪 | 一次已解析的 fs 调用 | 一棵真实的子进程树（`shell -c <command>`，`:65`），里面可以是任何解释器、任何语言 |
| 判据的落点 | **路径** | **进程** |

所以本票要定的是一个**判据落点**的取舍：判据落在命令文本上（候选 1 / 2），还是落在进程能碰到的资源上（候选 3），还是干脆取消这个能力（候选 4）。

**威胁模型沿用票 01 / 02**（人类拍定的口径，本票不改）：提示注入 + 模型自发探索，**不是**「防一个有界面访问权的对手」。`.github/SECURITY.md:28` 把这条界线写死了——「任何能摸到端口的东西都能直接调接口」，且「agent 执行有界面访问权的人给的指令」不算漏洞。本票的产出因此是**爆炸半径的收口**，不是攻防。

## Solution

**选定候选 3：文件系统层沙箱。** bash 交给操作系统级的约束执行，沙箱的允许面由**与路径守卫同一份**允许根判定生成。

### 为什么是候选 3

因为它是四条候选里**唯一能把判据落到进程上**的一条：命令文本里出现什么、载荷藏在哪个文件里、用的是哪个解释器，都不影响判定——进程能不能 open 那个路径，由内核决定。前两条候选的失效方式不是「实现不够好」，而是「判据的对象错了」（逐条论证见 Implementation Decisions · 决策一）。

### 为什么不做成「命令解析」那种形态（判据落点，本票的核心判断）

文件工具的守卫能成立，靠的是一条**显式不变式**：非允许根一律不可达（ADR-0011 决策二）。bash 的文本判据给不出这条不变式——不是难，是**不可完备**。三条本机实测的反例（细节见 Further Notes）：

1. `sh <工作区内某脚本>`：命令文本里没有任何越界路径，载荷在文件里；
2. `node -e 'fs.readFileSync("<越界路径>")'`：路径是**数据**，不是命令文本的一部分；
3. `P=<越界目录> bash -c 'cat "$P/secret.txt"'`：字面量路径不存在于文本里。

只要文本判据要「能用」，就必须放行 `node` / `npm` / `git` / `bun` 一类解释器与包管理器；而放行它们等于放行任意代码——**被执行的代码可以住在工作区里的文件里**（脚本、`package.json` 的 script、Makefile），文本判据看不见它。于是白名单只有两种稳态：小到没有产品价值，或大到等于放行任意执行。

## User Stories

1. 作为人类 Owner，我想让成员的 shell 只能碰到它自己的家目录与显式绑定的项目目录，这样一次注入无法让它把 `~/.worksplice` 整片拖走。（决策一 / 二）
2. 作为人类 Owner，我想让「成员改用哪个解释器、把路径藏进脚本文件还是环境变量」都不影响判定，这样收口不是靠猜命令文本。（决策一）
3. 作为人类 Owner，我想知道成员 shell 的边界是「清单外一律不可达」而不是「尽量挡住」，这样我不会把一条启发式当成隔离。（决策二）
4. 作为人类 Owner，我想让成员自己的临时目录与只读工具链缓存照常可用，这样它跑 `node` / `npm` / `git` 不会因为收口而莫名其妙地失败。（决策二）
5. 作为人类 Owner，我想确定成员的 shell 读不到我的私钥与 GitHub token，这样一次注入不能把我的身份贴进频道；若它因此不能 `git push`，我要的是「响亮地不能」而不是悄悄放行。（决策二）
6. 作为人类 Owner，我想让沙箱跟着**会话归属的成员**走，而不是跟着某一个工具走，这样将来新增的 shell 面不会绕开它。（决策三）
7. 作为人类 Owner，我想在我自己的会话里敲 `!bash` 时进的是同一个沙箱，这样「成员会话」这条边界没有例外。（决策三）
8. 作为人类 Owner，我想在越界发生时看到的失败是可归因的——而不是让模型对着 `Operation not permitted` 反复换路径烧轮次——并且我在动手之前就能从工具描述里看到边界。（决策四）
9. 作为成员，我想知道我当前的允许根是哪几个绝对路径，这样我不用猜边界。（决策四）
10. 作为人类 Owner，我想在拿不到沙箱的平台上成员没有 bash，而不是悄悄按老样子跑，这样我不会误以为隔离已经生效。（决策五）
11. 作为人类 Owner，我想明确知道本形态挡不住什么——尤其 app 自己的接口面在 HTTP 票落地前仍是一条级联绕过——这样我不会把它当成隔离完成态。（决策六）
12. 作为开发者，我想允许面清单只写一处（与路径守卫同源的允许根判定），这样两层约束不会漂移。（决策一）
13. 作为开发者，我想这份清单带一套冒烟与负例可跑，这样「漏一条规则」不会变成线上莫名其妙的 SIGABRT。（决策二）

## Implementation Decisions

### 决策一（形态：判据落到进程）——选定候选 3，否决候选 1 / 2 / 4

判据的落点必须是**进程**：只有在内核这一层，才不关心命令文本里写了什么、载荷藏在哪个文件里、用的是哪个解释器。以下逐条写否决理由——**不是「解析难」，而是「不可完备」**。

#### 候选 1 · 受限 shell / 命令白名单解析 —— 否决

判据落在命令文本上，**不可完备**（Solution 的三条实测反例）。补充三点否决理由，按重要性排：

1. **载荷与调用分离**：`npm test` / `make` / `git -c core.pager=…` 这些被放行的调用，真正执行的代码在工作区的文件里。白名单检查的是那次调用，不是这次执行的内容。
2. **解析面本身就是逃逸面**：引号、`$'…'`、`${IFS}`、命令替换、heredoc、子 shell、别名与函数、`;`/`&&`/`|` 的语义差别——每一条都要穷尽，而穷尽之后仍然回到第 1 条。
3. **失效方向是静默放行**：漏一个形态 = 悄悄放过。路径守卫的 fail-closed（ADR-0011 D6 第三条）在文本判据上没有对偶——文本判据无法知道自己「漏了」。

#### 候选 2 · 路径重写（wrapper）—— 否决

与候选 1 同源（判据仍是文本），因此继承上面全部否决理由，另加两条它独有的：

1. **「哪些 token 是路径」本身不可判定**：`-C` / `-o` / `--file=` / `-t` 各自带路径，管道与重定向的右值也是路径，`find -exec` / `xargs` 把路径当参数传递，heredoc 往文件里写——覆盖不全不只是「还没写完」，而是没有一个可终止的枚举。
2. **逃逸面还包括变量与替换**：`$P/secret.txt`、`$(printf …)/secret.txt` 在文本里不呈现为路径；要处理就得先做完整的 shell 展开，那等于实现一个 shell。

#### 候选 3 · 文件系统层隔离（sandbox）—— **选定**

见 Solution。它的代价是真实的，一并写明：**平台分叉**（macOS `sandbox-exec` / Linux `bwrap` / Windows 无对应物）、**长尾允许项**（实测 `git --version` 都要读 `~/.gitconfig`，`node` 要能写 `TMPDIR`）、**脆**（漏关键规则时进程直接 SIGABRT，无 stderr）。这些是实施票要吸收的成本，不是否决理由——因为它是唯一能把「非允许根一律不可达」落到进程上的一条。

#### 候选 4 · 收掉 bash（档位层面）—— 否决（且属产品决策）

它是**唯一能把 HTTP 走廊一起关掉的形态**：成员没有执行与网络原语，也就够不到 app 自己的接口。但它同时推翻两条既有的**锁定**能力面（`docs/spec-bootstrap-agent.md:87-88`、`:289`）——「bash 开箱即用、curl 可用、零配置」，秘书经 `curl /api/*` 承担只读与创建类操作，验收项要求 7 条 curl 实测可用；并砍掉「成员能跑测试/构建」这个编码 agent 的核心承诺。产品决策不落在本票（人类已在第 1 轮定：不走它）。

**若将来产品决定收掉 bash**，档位语义的影响面清单在此，供那张票直接取用：

| 影响点 | 具体面 |

### 决策二（允许面形态：allow-only）

profile 是「清单内可达、其余一律不可达」，不是「现状 + 排除若干路径」。清单 = 成员允许根（家目录 + 显式绑定的项目目录）+ 系统只读面 + 进程自己的 `TMPDIR` + 只读工具链缓存。**用户级凭证不进清单**（`~/.ssh`、`~/.config/gh`、keychain 类）。

- **为什么不是 deny-list**：deny-list 更稳（不受漏规则之脆），但它给出的是一条**启发式**保证——只挡你枚举到的路径，与候选 1 / 2 的「不可完备」同源。形态的全部价值就是 ADR-0011 那条「非允许根一律不可达」，所以取 allow-only，代价（脆）用实施票的两条纪律吸收：profile 冒烟清单（node / npm / git / gh 各跑一条只读命令）与 exit 134 → 可读错误。
- **为什么凭证不进清单**：拿用户私钥/token 去换 `git push` 权，等于把「一次注入可把数据库贴进频道」换成「一次注入可把私钥贴进频道」，更坏。正解是**每成员凭证落在成员自己家目录**（本就在允许根内），建议落成后续票的输入。代价已知且响亮：成员 shell 不能 `git push` / `gh pr create`。
- **代价实测**：清单的长尾是真实的——同一份 profile 下 `git --version` 要读 `~/.gitconfig`，`node` 要能写 `TMPDIR`（见 Further Notes 的实测表）。人类已拍板（2026-10-06）。

### 决策三（覆盖的 shell 面：沙箱跟随会话归属的成员）

不是「bash 工具的沙箱」，是「**会话归属成员的**沙箱」：工具面与 `lib/rpc/session.ts:746` 的 RPC 面走同一判定；无人归属的会话（人类自己的会话）不沙箱。理由是这条规则是会话属性而非工具属性，将来新增的 shell 面自动被覆盖。代价：人类在成员会话里敲 `!bash` 也进沙箱。人类已拍板（2026-10-06）。

### 决策四（越界处置：机制替换，意图不变）

机制换成内核的 `Operation not permitted`；ADR-0011 决策五（D7）的意图以两条方式保留——该成员的允许根写进**注册期的工具描述**（边界先于撞墙），包装层把 EPERM 与 exit 134（SIGABRT）归因成可读错误。仍**不静默改写、不静默截断**。

### 决策五（平台：fail-closed）

macOS 用 `sandbox-exec`（实测可用、deprecated、脆）；Linux 用 `bwrap`（未在本机验证，实测后才能声称覆盖）；Windows 无对应物。**拿不到沙箱就不激活 bash**，并让档位展示能解释这件事——静默 fail-open 会让隔离承诺变成平台相关且不可见。这一条**不是人类拍的**：是 coordinator 代答，仍待人类追认（见 Solution 的表下注）。

### 决策六（排序约束：HTTP 走廊是前置条件，不是并列残留）

人类在第 1 轮把这一条从「残留清单」改判为「排序链」，理由成立，照此落：

```text
HTTP 走廊票（让 app 不再给任何调用者一条未沙箱的裸 shell）
  → sandbox 实施票（本形态）
    → 至此 bash 收口才成立
```

链条的事实依据：

1. `POST /api/agent/[id]` 接受**任意**命令（`app/api/agent/[id]/route.ts:17`、`:26`），`{"type":"bash"}` 由此进入 `lib/rpc/session.ts:746` → `AgentSession.executeBash`，而后者用的是**裸本地实现**（`dist/core/agent-session.js:3037` 的 `options?.operations ?? createLocalBashOperations({ shellPath })`，worksplice 不传 operations）——**未沙箱、不经过六工具守卫**。
2. 这条路由**没有调用者身份**：进门的请求一律按 Owner 处理（`lib/domain/collab/channels.ts:7` 的 `CURRENT_MEMBER_ID`），任何能摸到端口的东西都能调（`.github/SECURITY.md:28`）。
3. 因此它**同样使票 02 的六工具守卫失效**（那两个守卫挂在工具定义上，而这条路径根本不走工具）→ 它是**票 02 收口的前置条件**，不是本票的收尾。
4. 在它落地之前，票 02 与本形态都必须自述为「**纵深防御的一层**」，不得声称隔离完成。

**给 HTTP 走廊票的输入（本票只写约束，不做它的决策）**：秘书的 curl 能力面是锁定条目（`docs/spec-bootstrap-agent.md` §3.1 / §3.3），所以不能简单封端口；正确形态是给内部调用者**受控凭证或专用通道**——这是那张票的决策。另需注意：**别把例外做成「秘书豁免」**——秘书是每个频道都在、最容易被注入的成员，给它开特权等于把收口开在被注入概率最高的地方。

### 决策的后果：残留绕过面

**本形态落地之后，仍能越界的有**（按严重度排）：

| # | 残留面 | 说明 |
| --- | --- | --- |
| 1 | **HTTP 走廊** | 见决策六。它是级联面：在 HTTP 票落地前，成员可以两段式绕过——`curl` 让 app 代跑一条未沙箱的裸 shell，sandbox 的实际隔离效果为零。 |
| 2 | 其它本机服务与同机进程 | 沙箱约束的是「成员 shell 能碰到哪些路径」，不是「成员不能与本机其它东西说话」。同一台机器上的其它 loopback 服务仍是成员 shell 能碰的。 |
| 3 | 清单里的附加项本身 | `TMPDIR` 是同一用户共享的（可读到别人的临时文件）；工具链缓存目录里可能留着别的项目的文件内容。 |
| 4 | 平台差异 | 非 macOS 的姿态见决策五（fail-closed）。Linux 侧（`bwrap`）本机未验证，实施票必须实测后再声称覆盖。 |
| 5 | 扩展 / 包提供的工具 | `withExtensionTools`（`lib/rpc/session.ts:707` 一带）把扩展工具与内置工具一起激活。一个提供任意执行或网络能力的第三方工具就是一条新的绕过面，**不在本形态与票 02 的守卫内**——本票只记账。 |
| 6 | TOCTOU | 与 ADR-0011 D6 同一条已知残留：判定与实际 IO 之间的窗口不处理（威胁模型不是能在毫秒级窗口里抢符号链接的对手）。 |
| 7 | 允许根**之内**的破坏 | 路径收口不是意图审查：成员仍能在共享项目目录里写坏代码、把读到的内容贴进频道。 |
| 8 | 人自己那一路 | 人类是 Owner：自己的终端、自己会话里的 `!bash`（无人归属的会话不沙箱）不在威胁模型内。 |

## Testing Decisions

**本票不跑测试**（决策票，源码改动面为空，决策文档没有被测对象）。以下是**实施票**的测试面，作为形态的一部分交付：

- **单元层（注入 fake `operations`）**：断言 `ops.exec` 收到的是**原样命令**与正确的 `cwd`/`env`；断言 env 里的 `WORKSPLICE_*` 已被清掉；断言 profile 由允许根派生（改允许根 → profile 跟着变）。
- **集成层（真沙箱，平台相关，可跳过）**：越界读被拒（`Operation not permitted`）、越界写被拒、允许根内读写与不装沙箱时**输出一致**、`git --version` / `node -e` 这类「长尾命令」在清单下能跑。
- **覆盖断言**：RPC 面（`session.send({type:"bash"})`）与工具面走**同一个**沙箱判定（否则本形态白装）。
- **既有先例**：`node:test` + `node:assert/strict`，测试文件后缀 `.test.mjs`；门禁 `tsc --noEmit` + lint（只报告不 `--fix`）+ `node --test`，**绝不 `next build`**。

## Out of Scope

- **不改代码**：本票源码改动面必须为空（若必须改代码才能完成本票，说明票型判错了）。
- **不改档位构成**（候选 4）：改 `PRESET_DEFAULT` 牵动 `lib/tool-presets.ts` 与 UI 档位语义，属产品决策，不落在本票。
- **不动 HTTP 层**：排序链的第一环另票；本票只写约束与输入。
- **不设计命令白名单 / 路径重写**：候选 1/2 已否决，机制不进实施范围。
- **不做每成员凭证**：本票只写「成员 shell 不读用户级凭证」这条约束与它的代价（成员不能 `git push` / `gh pr create`），正解（每成员凭证落在成员自己家目录）建议另票。
- **不做 TOCTOU 加固**、**不做人在环审批**（沿用票 01 / 02 的口径：隔离优先、可观测性另议）、**不改消息 / 频道 / 唤醒 / 任务语义**。

### 后续实施票要解决什么

本票**不实施**。实施票从本票 resolved 之后另开，要解决：

1. **profile 生成器**：从 `allowedRootsFor(member)`（票 02 的判定）生成 allow-only profile，保持单一事实来源（ADR-0007 决策 5）。
2. **平台适配器与 fail-closed 姿态**：macOS `sandbox-exec`；Linux `bwrap` 实测后再声称覆盖；Windows 无沙箱 → bash 不激活，且档位展示要能解释「本平台没有 bash」。
3. **覆盖全部 shell 面**：工具面 + `lib/rpc/session.ts:746` 的 RPC 面，按「会话归属的成员」决定沙箱；无归属的会话不沙箱。
4. **清单的冒烟与负例**：node / npm / bun / git / gh 各跑一条只读命令（证明清单够用）；越界读、越界写各一条负例（证明清单够严）；SIGABRT（漏规则）必须转成可读错误。
5. **边界可见性（D7 的机制替换）**：把成员的允许根写进注册期的工具描述；越界时的输出要能归因到沙箱，而不是让模型对着 `Operation not permitted` 反复换路径烧轮次（`MUST_RESPOND_FAILURE_CAP = 2`，ADR-0005）。
6. **env 收口**：清掉 `WORKSPLICE_*`（app 自己的秘密），保留用户自己的环境变量（那是用户的选择）。
7. **档位展示的一致性**：fail-closed 平台上「档位显示 full/default、实际没有 bash」必须有解释，不允许静默不一致。

明确**不做**：不做命令解析（候选 1/2 的机制）、不改档位构成（候选 4 属产品决策）、不动 HTTP 层（那是排序链的第一环，另票）、不设计每成员凭证。

## Further Notes

### 本机实测记录（2026-08，macOS 26.5.1 / arm64）

| 实测 | 结果 |
| --- | --- |
| `/usr/bin/sandbox-exec` 是否还可用 | 可用（deprecated 但仍工作） |
| allow-only profile 拦根外**读** | `cat: …: Operation not permitted` |
| allow-only profile 拦根外**写** | `touch: …: Operation not permitted`；清单内写放行 |
| allow-only profile 漏关键规则 | 子进程 **SIGABRT**（exit 134，无 stderr）——第一版 profile 就踩到，这是「脆」的实感 |
| `git --version`（清单不含 `~/.gitconfig`） | `fatal: unable to access '/Users/apple/.gitconfig': Operation not permitted` |
| `node` 写 `os.tmpdir()`（清单不含 `TMPDIR`） | `EPERM: operation not permitted, open '/var/folders/…/T/…'` |
| `(deny network* (remote ip "*:<port>"))` | **只封指定端口**：同机其它 loopback 端口与出网都不受影响 |
| `(deny network* (remote ip "localhost:*"))` | 连出网一起封（不是「只封 loopback」的写法）——网络过滤要按端口写 |
| 文本判据的三条逃逸 | `sh <工作区内脚本>`、`node -e 'readFileSync(越界路径)'`、`P=<越界目录> bash -c 'cat "$P/secret.txt"'` 全部读出内容 |

（网络那条本票**不使用**：见决策六——app 自己的接口面由 HTTP 票处理，本形态不封端口，因为秘书的 curl 能力面是锁定条目。记在这里是为了让实施票知道这条路是通的，以及写法的坑。）

### 与 ADR 的关系

- **建 ADR-0012**：三条件全满足——① **难以逆转**：形态定稿后，profile 政策、平台适配、允许面清单就是隔离基线，改口径要重做；② **无上下文会惊讶**：后来者会问「为什么成员 shell 连 `~/.gitconfig` 都要额外允许」「为什么 macOS-only」「为什么沙箱跟着会话而不是工具」「为什么这条路要等 HTTP 票」——都是刻意的；③ **真实权衡**：四条候选 + 允许面形态（allow-only vs deny-list）+ 凭证长尾 + 网络 + 平台五处取舍。
- **不重开**：注入点、允许根构成、越界处置形态由 **ADR-0011** 钉死，本票沿用（bash 的越界「机制」换成内核拒绝，但 D7 的意图——报边界、不静默改写、不静默截断——不变，属机制替换而非决策重开）。
- **既有覆盖不新立**：家目录与共享项目目录两分在 ADR-0001；`pi 管 pi` 与「同一事实不写两处」在 ADR-0007；分层与依赖方向在 ADR-0008。
- **`.github/SECURITY.md`** 是既有暴露面口径（本地单机、接口可达即 shell 可达、agent 执行有界面访问权者给的指令不算漏洞），本票的威胁模型与它对齐，不与之冲突。

### 术语

「**沙箱 (Sandbox)**」入 `CONTEXT.md` 的 `## Language`。既有词条「允许根」的 _Avoid_ 原把「沙箱」列为同义禁词（那时它只是实现说法）；现在沙箱是一个**独立而更低的层**，两个词条互相指引，不再互斥。
