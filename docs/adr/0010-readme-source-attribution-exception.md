# 品牌脱钩照旧，README 留一处出处声明：收窄 spec §7.2 第 2 行

**原决策与意图**：`docs/spec.md` §7.2「命名与品牌脱钩」共 8 项（ticket 06，**[锁定]**），意图是让 worksplice 不被误认成 pi-web 的换皮或官方续作——worksplice 是独立产品、独立命名、独立品牌。它点名要删的是**品牌标识**那一类东西：badge、截图、logo、favicon、页面标题与文案、项目名、包名、环境变量前缀、内部标识符（§7.2 第 4/5/6/7/8 项）。**这套意图今天依然成立，本 ADR 不推翻它**：读者看到 worksplice 时不应被引导以为它仍是 pi-web 的一个版本。分歧只出在第 2 项把「删品牌标识」与「删出处」写进了同一句，而这两件事方向相反。

**为什么要收窄第 2 行**：脱钩（隐藏来源）与出处声明（承认来源）方向相反，把两者塞进同一句，判据就消失了——后来任何人往 README 里加一句出处，无法判断这算不算违反 §7.2 第 2 项。本票开工时正是卡在这一点上停下来的：写不写致谢，两种做法都能援引第 2 行的字面。把两件事拆开，规则才可机械判定。另有两点实质理由：

- `agegr/pi-web` 是 MIT 许可、6997 star、**至今仍在活跃维护**（`gh api repos/agegr/pi-web`：`stargazers_count=6997`、`archived=false`、`pushed_at=2026-10-01`），而 worksplice 的代码起始于它的源码。对一个仍在被他人使用与 fork 的项目隐去来源，是净损失。
- MIT 只要求在 `LICENSE` 里保留版权声明——§7.2 第 3 项已经做到，**法律义务其实已经满足**。但让署名只存在于法律文本、对 README 的读者完全沉默，既不合 MIT 的精神，也不合 MIT 之外的工程惯例。**所以收窄不是补法律义务，是补署名**：法律底线由 LICENSE 承担，README 这一处是给人看的。

**收窄后的判据（可机械判定）**：README 中 `agegr/pi-web` 只允许出现在 Acknowledgements / 致谢小节内，且必须与 pi（运行时底座）的致谢分开陈述——两处致谢性质不同，pi-web 是源码的来源处，pi 是至今仍在读取并驱动的运行时，混写会把「衍生自」说成「构建于」。**不得**出现 pi-web 的 badge、logo、截图、favicon 或页面文案。

**Consequences**: §7.2 第 2 项从「删 pi-web 链接/badge/截图」收窄为「删 badge/截图/logo/品牌文案 + 保留一处出处声明」，其品牌脱钩效力不变；新增本 ADR 的可判定判据，此后往 README 加 pi-web 链接不再需要逐次回头修 spec——符合判据即为合规，超出即为违规。README 与 README.zh-CN.md 各一处致谢小节同步维护（新增文案时两份一起改）。原判断「README 里出现 pi-web 字样 = 违规」不再成立，但 pi 与 pi-web 的致谢不得互相吞并（防止「构建于 pi」被读成「pi 的官方新版」）。若日后 pi-web 项目终止或 worksplice 完成全量重写、代码不再源自其实现，本出处声明可随之撤除，届时以新 ADR 取代本条。
