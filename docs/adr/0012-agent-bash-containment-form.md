# agent 的 bash 收口形态：判据落到进程（文件系统层沙箱），不落在命令文本

**背景**：票 02 把六个文件工具收进允许根之后，`bash` 是唯一剩余的绕过面。它与文件工具有一处决定性差别：文件工具的守卫拿到的是**已经解析好的绝对路径**（ADR-0011 D1），bash 的 `operations.exec(command, cwd, …)`（`dist/core/tools/bash.js:261`）拿到的是**整条命令字符串**，越界行为发生在它起的一棵子进程树里——判据的落点从「路径」变成「进程」。本决策定的是这个落点。

**决策一（形态：判据落到进程）**：bash 交给**操作系统级沙箱**，沙箱的允许面由与路径守卫**同一份**允许根判定生成（不改 ADR-0011 的注入点、允许根构成与越界处置意图，只把同一接缝用在第二个工具上）。候选 1（受限 shell / 命令白名单解析）与候选 2（路径重写）**否决**，理由不是「解析难」而是**不可完备**：判据落在命令文本上时，`sh <工作区内脚本>`、`node -e 'readFileSync("<越界路径>")'`、`P=<越界目录> bash -c 'cat "$P/secret.txt"'` 三条实测路径都能读出内容，且被放行的 `npm test` / `make` 执行的代码住在文件里，文本判据看不见；文本判据也无法知道自己漏了什么（路径守卫的 fail-closed 没有对偶）。候选 4（收掉 bash）**否决**：它是唯一能连带关掉 HTTP 走廊的形态，但推翻 `docs/spec-bootstrap-agent.md:87-88`/`:289` 的**锁定**能力面（秘书经 `curl /api/*` 承担只读与创建类操作，验收要求 7 条 curl 实测可用），属产品决策。

**决策二（允许面形态：allow-only）**：profile 是「清单内可达、其余一律不可达」，不是「现状 + 排除若干路径」。清单 = 成员允许根（家目录 + 显式绑定的项目目录）+ 系统只读面 + 进程自己的 `TMPDIR` + 只读工具链缓存。**用户级凭证不进清单**（`~/.ssh`、`~/.config/gh`、keychain 类）：拿用户私钥/token 去换 `git push` 权，等于把「一次注入可把数据库贴进频道」换成「一次注入可把私钥贴进频道」，更坏；正解是每成员凭证落在成员自己家目录（本就在允许根内），另票。代价已知：成员 shell 不能 `git push` / `gh pr create`；清单的长尾是真实的（实测同一份 profile 下 `git --version` 要读 `~/.gitconfig`，`node` 要能写 `TMPDIR`），漏关键规则的失败模式是子进程 SIGABRT（无 stderr）——实施票必须带冒烟清单与 134 的可读化。

**决策三（覆盖范围：沙箱跟随会话归属的成员）**：不是「bash 工具的沙箱」，是「会话归属成员的沙箱」——工具面与 `lib/rpc/session.ts:746` 的 RPC 面走同一判定；无人归属的会话（人类自己的会话）不沙箱。理由是这条规则是会话属性而非工具属性，将来新增的 shell 面自动被覆盖。代价：人类在成员会话里敲 `!bash` 也进沙箱。

**决策四（越界处置：机制替换，意图不变）**：机制换成内核的 `Operation not permitted`；ADR-0011 决策五的意图以两条方式保留——该成员的允许根写进**注册期的工具描述**（边界先于撞墙），包装层把 EPERM 与 exit 134 归因成可读错误。仍**不静默改写、不静默截断**。

**决策五（平台：fail-closed）**：macOS 用 `sandbox-exec`（实测可用、deprecated、脆）；Linux 用 `bwrap`（未在本机验证，实测后才能声称覆盖）；Windows 无对应物。**拿不到沙箱就不激活 bash**，并让档位展示能解释这件事——静默 fail-open 会让隔离承诺变成平台相关且不可见。

**决策六（排序约束：HTTP 走廊在前）**：`POST /api/agent/[id]` 接受任意命令（`app/api/agent/[id]/route.ts:17`、`:26`），`{"type":"bash"}` 由此进入**未沙箱**的裸本地实现（`dist/core/agent-session.js:3037`），且这条路由没有调用者身份——任何能摸到端口的东西都能调（`.github/SECURITY.md:28`，进门一律按 Owner 处理）。它**同样使票 02 的六工具守卫失效**（该路径不走工具）。故链条是：**HTTP 走廊票 → sandbox 实施票 → bash 收口才成立**；在 HTTP 票落地前，票 02 与本决策都只能自述为「纵深防御的一层」。给那张票的输入：秘书的 curl 能力面是锁定条目，所以不能简单封端口，要给它受控凭证或专用通道——且**不做「秘书豁免」**（秘书在每个频道、最易被注入）。

**Consequences**：

- 本决策收口的是「成员 shell 能碰到哪些**路径**」，不是「成员看不到哪些**数据**」。首要残留是 HTTP 走廊（见决策六），其余：同机其它 loopback 服务、清单附加项自身（共享 `TMPDIR`、缓存目录里的他项目内容）、扩展/包提供的工具（提供任意执行或网络能力的第三方工具是新的绕过面，只记账）、TOCTOU（沿用 ADR-0011 D6）、允许根之内的破坏（路径收口不是意图审查）。
- 不重开 ADR-0011：注入点、允许根构成、越界处置形态沿用；本决策只新增「bash 与它的机制层」这一层。家目录两分在 ADR-0001，切分线与「同一事实不写两处」在 ADR-0007，分层方向在 ADR-0008。
- 实施票另开（本票不实施）：profile 生成器、平台适配器与 fail-closed、两个 shell 面的接线、冒烟与负例、边界可见性、env 收掉 `WORKSPLICE_*`（`getShellEnv()` 是 `{...process.env}`，`dist/utils/shell.js:117-124`）、档位展示的一致性说明。
- 术语「沙箱 (Sandbox)」入 `CONTEXT.md`；设计全文见 `docs/agent-bash-containment-form.md`。
