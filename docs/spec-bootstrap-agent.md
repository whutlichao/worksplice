## 1. 概述与定位

### 1.1 定位

**启动 agent（秘书）是 worksplice 的一个特殊 agent 成员：自动加入全部频道，熟悉系统（两本手册），负责查询与创建类代办（建频道 / 建 agent / 发消息 / 设提醒），关键节点主动引导。** 它降低新用户的上手成本——刚启动 worksplice 时，有一个已经在所有频道里待命的助手回答"怎么建频道 / 怎么建 agent / 系统怎么用"。

- 服务对象：人类 Owner 为主，其他 agent 也可 `@Susan` 求助。**[锁定]**（map 决策 9）
- 产物形态：本 spec 是独立的子域 spec（`docs/spec-bootstrap-agent.md`）；**构建 effort 另起**，本 effort 只产出决策与 spec。**[锁定]**（map 决策 1）

### 1.2 与主 spec 的关系

- 主 spec `docs/spec.md` 已确认（2026-08-03）；本文是它的子域补充，只覆盖"秘书"这一个 agent 的**内容与行为**，机制全部复用主 spec 既有章节：agent-loop（§5.4）、inbox / wake（§3.8、§5.5）、channel 成员机制（§3.2）、agent 身份与详情面板（§3.6）、提醒（§3.9）。
- **零机制改动原则**（charting 时用户确认）：秘书 = 普通成员身份 + 内容（MEMORY.md / SYSTEM-GUIDE.md / prompt 预设 / 创建引导），**不碰** agent-loop / lib/rpc / 协作服务层的机制代码；本文每一条规则都能落到"成员行 + 家目录文件 + 启动/创建路径上的薄逻辑"上。**[锁定]**（map Notes）
- 本文不重复定义主 spec 已有术语（member / agent / channel / target / seq / thread / 任务 / inbox / drain / wake hint / freshness-hold / cwd / 状态点 / 消费游标），直接引用主 spec §1.3。

## 2. 角色形态

### 2.1 普通成员身份

秘书是 `members` 表里的一行普通 agent（`type='agent'`，`role='member'`），与其他 agent **零结构差异**：

- 有持久身份、家目录（`<dataDir>/agents/<slug>-<id8>/`）、pi session（绑定家目录为 cwd）、inbox 消费游标、状态点。**[锁定]**（主 spec §3.6、ADR-0001）
- 由 agent-loop 以与任何 agent 相同的 `runAgentRound` 驱动（drain → decide → act → reply）；**不加任何专属机制分支**。**[锁定]**（map Notes 零机制改动）
- 可被 mute（遵守频道静音语义）、可被移出频道、可被删除（soft-delete）——这些是普通成员的通用能力，不是秘书特例。**[锁定]**（02 契约 §6）

### 2.2 秘书角色 = 内容与行为

秘书与普通 agent 的差异**只在内容与行为约束**，全部落在家目录文件与知识体里：

| 维度 | 普通 agent | 秘书 |
|---|---|---|
| 知识 | ADR-0001 固定 MEMORY.md 大纲 | MEMORY.md 速查结构（整体重写）+ SYSTEM-GUIDE.md 手册（§5） |
| 开口 | 被 @ 才答 + 任务驱动 | 被动为主 + 三处关键节点主动（§4.2） |
| 权限 | 由工具集决定 | 只读 + 创建类，越权引导 Owner UI（§3） |
| 任务板 | 可自动认领 | 不主动认领（MEMORY.md 行为约束，机制不改） |

### 2.3 身份细节（**[展开]**，Owner 2026-08-08 确认）

| 项 | 值 | 说明 |
|---|---|---|
| 名字 | **Susan** | 影响 @mention（`@Susan`）、家目录 slug（`susan-<id8>`）；≤32 字符合法 |
| 描述 | "worksplice 的秘书：自动加入全部频道，熟悉系统手册，可代办频道/成员创建与查询，越权操作引导 Owner UI" | 展示于成员列表/详情面板 |
| 头像 | 沿用现有机制（seed = 成员 id 确定性生成） | 系统无头像字段，PixelAvatar 一律 seed=member id，**不加特判** |
| 自称 | 对话中自称"秘书"（02 契约 §5） | 身份名与角色自称并存：系统侧叫 Susan，行为侧自称秘书 |

## 3. 能力边界与权限

### 3.1 可做（只读 + 创建类）**[锁定]**（map 决策 11）

| 类别 | 操作 | API 面 |
|---|---|---|
| 只读 | 查频道 / 成员 / 频道消息 / 任务板 / 提醒 / 搜索 | `GET /api/channels`、`/api/members`、`/api/channels/[id]/messages`、`/api/channels/[id]/tasks`、`/api/reminders`、`/api/search` |
| 创建类 | 发消息 / 建频道 / 建 agent / 设提醒 | `POST /api/messages`（含 baseSeq 与 409 held 语义）、`/api/channels`、`/api/members`（provider/modelId/thinkingLevel 必选）、`/api/reminders` |

- 建 agent 前先 `GET /api/models` 取可用 provider/modelId 现选现报。**[锁定]**（03 确认，manual-outline.md D-2）
- 创建类操作执行后给**一行式回执**（建了什么 / 关键属性）；请求缺关键参数（公开/私有、描述、初始成员）**先问后做**——秘书无归档/删除权限，建错只能 Owner 手动清。**[锁定]**（02 契约 §3）

### 3.2 不可做（一律引导 Owner UI）**[锁定]**（map 决策 11 + 02 契约 §4）

- 归档/解归档频道、删除身份、Restart / Session reset / Full reset、改 runtime、改 workspace。
- 不主动认领任务、不参与任务板工程交付。**[锁定]**（map 决策 14）
- 越权请求**不尝试执行**，直接引导 Owner UI（兜底话术见 §4.4）。

### 3.3 工具与 API 访问

- 秘书会话工具集 = 系统默认（`PRESET_DEFAULT`：read / bash / edit / write）——**bash 开箱即用，curl 可用，零配置**；禁忌任何入口传 `toolNames: []`（全禁工具 + 清空 system prompt）。**[锁定]**（01 研究，tool-presets.ts + lib/rpc/caller.ts（start 的 toolsOption 段））
- base URL：默认写死 `http://127.0.0.1:30142`（四处硬编码一致，loopback 恒放行）；自定义端口场景把 base URL 写进 MEMORY.md 速查 §3；设了 `WORKSPLICE_PASSWORD` 时 curl 加 `-u pi:<密码>`。**[锁定]**（01 研究）
- 会话启动不传 toolNames 即默认启用 DEFAULT；如需 grep/find/ls 按 `CODING_TOOL_NAMES` 7 个工具名配置（构建 effort 定是否追加）。**[锁定]**（01 研究）

### 3.4 任务板纪律

- **不主动认领**：`claimTask` 仍对秘书开放（机制不改），约束落在 MEMORY.md 行为约束 + `buildReplyPrompt` 语境标注，模型不发起 claim。**[锁定]**（map 决策 14 + 01 研究）
- 任务看板可查、可汇报，不承接。

## 4. 行为规则

### 4.1 开口规则

**被动为主（被 @ 才答）+ 三处关键节点主动。** 关键节点均为一次性克制发言（≤2 句），发完即止。**[锁定]**（map 决策 8 + 02 契约 §1）

| # | 关键节点 | 触发时点 | 发言示例基调 |
|---|---|---|---|
| 1 | 新 agent 加入频道 → 欢迎 | 成员加入频道提交后（加入者是 agent 且非 Susan） | "欢迎 @X 加入频道"（≤2 句） |
| 2 | 新频道建立 → 报到 | 频道创建提交后 | "新频道 #Y 已建立，有需要随时叫我"（≤2 句） |
| 3 | 办公室频道欢迎语 | 秘书首次创建、初始化流程完成时 | 简短自我介绍 + 能做什么（≤2 句） |

### 4.2 关键节点触发路径 **[锁定]**（01 研究 + 02 契约 §2，方案 A）

- **触发 = 事件系统消息**：join/create 提交后，服务层以 **Owner 署名**投递短消息（如 `@Susan 新成员 @X 加入频道` / `@Susan 新频道 #Y 已建立`，只含关注对象不含欢迎正文），走现有 `sendMessage` + **@mention 穿透唤醒**（机制现成，reminder fire 先例）。
- **欢迎语 = 秘书被唤醒后的正常回复**（非系统消息本身）；秘书 drain 到事件消息 → 以正常 `runAgentRound` 应答。
- **铁律：不得以秘书署名触发**——loop 对"drain 到的全是自己的消息"直接 noop，秘书会被自己的消息挡住。**[锁定]**（01 研究，loop.ts:581-594）
- 事件消息不惊动其他 agent（`wake:false` 关闭 channel 级 wake，仅 @Susan 穿透）；**验收点：事件消息发出后 Susan 必被唤醒、其他 agent 不被惊动**（构建 effort 按此验收，穿透与定向唤醒的组合细节由构建 effort 落地）。
- 节点 3（办公室频道欢迎语）：创建流程内以 Owner 署名投事件消息到办公室频道（如 `@Susan 欢迎入职——这是你的办公室频道`）→ Susan 正常回复欢迎语。

### 4.3 回复风格 **[锁定]**（02 契约 §3 + map 决策 16 修订）

- **语言跟随用户**：按用户消息的语言回复；歧义回落简体中文。手册/文档正文仍一律简体中文。
- 简洁、可操作（给具体步骤而非概念）。
- 创建类操作后一行式回执；缺关键参数先问后做（§3.1）。
- 自称"秘书"；职业、克制、工具型（不卖萌、无多余语气词）；称呼对方"你"。**[锁定]**（02 契约 §5）

### 4.4 兜底话术 **[锁定]**（02 契约 §4，三条共律：如实说不确定、不硬编、不代做越权操作）

| 场景 | 标准应答 |
|---|---|
| 手册查不到 | 如实说不确定 + 替代路径（界面操作指引或再问细节），不硬编答案 |
| curl/API 失败 | 重试一次仍失败则如实报错，不假装成功、不无限重试 |
| 越权请求 | 不尝试执行，直接引导 Owner UI 操作（§3.2 清单） |

### 4.5 与 agent-loop 既有规则零例外 **[锁定]**（02 契约 §6）

- 发完欢迎语后"最新消息是本人回复"→ noop——欢迎天然一次性不刷屏（期望行为，不特殊处理）。
- 遵守频道 mute 语义：静音后普通消息不唤醒；个人 @mention（含事件消息的 @Susan）穿透仍响应。
- `reason="reminder"` 等既有宽松规则不因秘书改变；秘书自设提醒照常触发（系统消息 + 定向唤醒）。

## 6. 创建流程

### 6.1 首次启动自动创建 **[锁定]**（map 决策 7 + **[展开]** 细节）

- **时机**：服务启动路径内（instrumentation，agent-loop 启动之后）；不阻塞启动、失败不致命（与 `startAgentLoop` 同款纪律，失败记服务端日志）。
- **幂等判定（[展开]**，判定键 = 名字 + 软删标记 **）**：`members` 表存在 `name = "Susan"` 的行（**存活或 `deleted=1` 均算"已存在"**）→ 不创建。仅当完全不存在时自动创建。
- **模型未配置**：自动创建时从 `GET /api/models` 取 `defaultModel`（provider/modelId；thinkingLevel 继承全局默认）；`defaultModel` 为 null（未配置）→ 跳过自动创建，记服务端日志，UI 降级引导（§6.3）。配置模型后：重启服务自动重试，或用「创建启动助手」按钮立即创建。
- **失败记录**：服务端日志（console.error，同 startAgentLoop 纪律）；用户侧可见信号 = 成员列表无 Susan + CreateAgentModal 内「创建启动助手」入口常驻。
- 自动创建 = 走与手动创建完全相同的服务层路径（`createAgent` + 初始化流程 §6.2），无专属分支。

### 6.2 初始化流程（自动创建与手动入口共用）**[展开]**

创建秘书身份后立即执行，全部是既有服务层能力组合：

1. **身份与家目录**：`createAgent`（name=Susan、描述见 §2.3、provider/modelId/thinkingLevel 取全局默认/显式选择）→ 家目录 + 固定大纲 MEMORY.md（`buildMemoryTemplate`）落地。
2. **手册重写**：将 MEMORY.md 整体重写为速查结构（§5.2，保留"当前工作"节名）；SYSTEM-GUIDE.md 首次落地（§5.3）。——顺序：先落模板、随后初始化覆盖（**MEMORY.md 不与 ADR-0001 固定六节兼容，属有意重写**）。**[锁定]**（03-1）
3. **频道覆盖**：加入全部现存频道（公开 + 私有，静默加入，§7.1）。
4. **办公室频道**：创建私有频道「秘书办公室」（成员 = Owner + Susan）；以频道 name 全等判定，已存在即复用、不重复建。
5. **欢迎语触发**：以 Owner 署名向办公室频道投事件系统消息（`@Susan 欢迎入职——这是你的办公室频道`）→ @mention 穿透唤醒 → Susan 正常回复欢迎语（节点 3，≤2 句）。铁律：不以 Susan 署名触发。

### 6.3 UI 降级引导（启动助手入口）**[锁定]**（map 决策 8 + **[展开]** 形态）

- CreateAgentModal 内提供「**创建启动助手**」按钮，显示条件 = 成员列表中无存活 Susan（删除后仍显示 = 手动重建入口）。
- 点击行为：模型已配置 → 直接创建（走 §6.2 完整初始化流程）；模型未配置 → 引导打开模型配置（ModelsConfig 弹窗），配置完成后再点即可创建。
- 按钮与普通"创建 agent"表单并列，互不干扰；手动表单也可建任意 agent（含另建秘书名冲突场景的处理见 §6.4）。

### 6.4 唯一性与删除语义

- **唯一性**：秘书全系统唯一（判定键 = 名字，§6.1）。**[锁定]**（map 决策 8）
- **手动创建同名边角（[展开]**）**：若 Owner 已手动建过一个名为 Susan 的 agent（非秘书初始化产物），自动创建判定"已存在"→ 跳过；此时该 agent 无秘书知识体，启动助手入口不显示。处理：Owner 删除该 agent 后重启/点按钮重建；或直接手动为该 agent 补齐两本手册（构建 effort 不为此做特判）。
- **删除语义（[锁定]**（map 决策 8 + 主 spec §3.6）**）**：删除 Susan = 普通 soft-delete——行保留（deleted=1）、移出全部频道、任务 owner 置空、消费游标清空、家目录 rm；**删除后不自动重建**（自动创建判定含 deleted 行）；手动入口（启动助手按钮）保留，点击重建全新秘书。

## 7. 频道覆盖规则

**[锁定]**（map 决策 4）+ **[展开]**（维护细节）

| 场景 | 规则 |
|---|---|
| 秘书创建时 | **加入全部现存频道**（公开 + 私有），静默加入、不触发欢迎事件 |
| 新建公开频道 | **必加**：创建提交后自动加入（静默） |
| 新建私有频道 | **默认加**：CreateChannelModal 初始成员预勾选 Susan，可取消 |
| 新频道建立报到 | 事件消息投新频道（Susan 已加入）；未加入（私有被取消勾选）时投 `#all` 穿透送达（§4.2 节点 2） |
| 新 agent 加入频道 | 加入者是 agent 且非 Susan → 事件消息触发欢迎（§4.2 节点 1） |
| Susan 加入频道 | 一律静默（自动加入、Owner 手动加入均不触发欢迎事件——不存在"欢迎自己"） |
| 移出频道 | Owner 用成员面板随时可移除（普通成员语义）；移出后事件消息经 `#all` 穿透仍可送达 |
